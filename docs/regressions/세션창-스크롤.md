# 세션창/스크롤 회귀 방지 규칙

> 이 영역을 수정할 때만 읽는다. 규칙은 실제 사고에서 얻은 불변식이며, 구현이 바뀌면 현재의 올바른 경로만 남도록 갱신한다.

- **본문 전체 재렌더 경로는 `preserveReadingPosition` 으로 보던 지점을 재중앙한다.** — 인라인 삽화 이미지 재로드로 높이가 출렁이며 스크롤이 맨 위로 튀던 회귀(2026-07-08 수정). 대상: 생성 종료·오류·중단, 문단 재생성 [적용], undo 미리보기, undo/redo/형제 이동. 위치 계산 실패 시 저장 앵커를 지우지 않고, 복원 실패 폴백은 **항상 맨 아래**(맨 위 금지). 예외는 생성 중 followTail 뿐.

- **본문/번역 패널은 통째로 다시 만들지 않는다 — 바뀐 지점부터 끝까지만 다시 그린다.** — "맨 위로 튐"의 진짜 뿌리(2026-08-16). 이어쓰기 종료·재생성·번역 완료가 전부 `body.empty()`(또는 `translationEl.empty()`) → 전체 재생성이었다. 긴 세션에서는 (1) 그리는 동안 문서 높이가 무너져 브라우저가 스크롤을 그 높이로 clamp 해 버리고(= 위로 끌려감, 복원 코드가 뭘 하든 이미 늦음) (2) 매번 수천 개 span 을 새로 만들어 화면이 멎었다. → **본문**: `util/body-runs.ts` `buildBodyRuns`(displaySpans + 숨김 구간 → 런 목록, 순수 함수)로 렌더 계획을 만들어 `renderedRuns` 에 들고 있다가, 새 계획과 비교해 **실제로 달라진 런의 DOM 만** 갈아 끼운다(`patchBodyRuns` → `spliceBody`). 런 개수가 같으면(매크로 표시값 변경 `{{user}}`/`{{char}}`, 숨김 토글) 흩어진 그 자리들만 개별 교체하고 — **뒤에서 앞으로** 고쳐 앞쪽 offset 이 밀리지 않게 한다 — 개수가 바뀌면(이어쓰기/재생성/문단 재생성) 앞뒤 공통 부분을 뺀 가운데 한 구간만 교체한다. 화면에 보이는 앞부분 DOM 은 손대지 않으므로 스크롤이 움직일 이유 자체가 없다. **번역 패널**: 문단 구성(해시/원문/offset/개수)이 같으면 `syncTranslationBlocks` 가 바뀐 문단의 글자만 갈아 끼운다. 어느 쪽이든 계획과 DOM 이 어긋나면(미저장 편집이 버려지는 경우 등) 전체 렌더로 물러선다 — 그 판단은 `renderedRuns = []` 로 명시한다. **"일단 다 지우고 다시 그린 뒤 스크롤을 되돌리자"로 되돌아가지 말 것** — 그 방식이 이 이슈를 수십 번 재발시킨 원인이다.

- **본문 재렌더는 `renderBodySpans()` 를 직접 부르지 않는다 — 스크롤 복원을 소유한 경로(`preserveReadingPosition` 또는 `redrawBodyPreservingCaret`)를 통과한다.** — "맨 위로 튐"이 수십 번 재발한 진짜 이유는 계산 실패가 아니라 **복원을 아예 안 거치는 재렌더 경로가 계속 새로 생긴 것**이다(2026-08-16 수정). 실제로 비어 있던 곳: `redrawBodyIfDisplayChanged`(시나리오/페르소나/요약 변경으로 `{{char}}` `{{user}}` `{{summary}}` 표시값이 바뀔 때), `commitPending` 의 편집 확정 재렌더, QR 버튼 결과 붙이기(`applyQuickReplyText`) — 셋 다 복원 코드가 한 줄도 없었다. → (1) 전체 재렌더는 위 두 경로만, (2) 예외는 주석 `// scroll-owner: …` 로 누가 스크롤을 책임지는지 밝히고(최초 render, 집필 프로 변환의 픽셀 유지 2곳뿐), (3) **하네스(`tests/architecture-rules.mjs`)가 이 규칙을 강제**한다 — 새 호출부는 빌드가 아니라 하네스에서 잡힌다. 개별 호출부에 복원을 손으로 다는 방식으로 되돌리지 말 것.

- **복원은 "시도했다"가 아니라 "실제로 들어갔다"까지 확인한다 — 스크롤 대입이 무효인 순간(숨은 탭/높이 0)이 곧 맨 위 방치다.** — `preserveReadingPosition` 은 보던 지점을 못 잡으면(raw=null: 숨은 패널·매핑 실패) 아무것도 안 하고 끝났고, `clientHeight===0` 이면 재중앙도 조용히 걸러져 재렌더 직후의 `scrollTop=0` 이 그대로 남았다(2026-08-16 수정). → 재렌더 **전** 픽셀을 들고 있다가, ① raw 없음 = `rescueDroppedScroll`(0으로 떨어졌을 때만 픽셀 복귀), ② 높이 0 = `restoreTarget` 에 넘겨 ResizeObserver 가 크기 잡히는 순간 재시도. 챗 뷰 `renderMessages` 도 같은 규칙(`restoreScrollTop`, 값이 들어갈 때까지 몇 프레임 재시도).

- **커서가 본문 밖이면 커서를 "0"으로 복원하지 않는다.** — `getCaretOffset()` 이 선택영역이 본문에 없을 때 0을 돌려줘, 재렌더마다 문서 **맨 앞**에 커서를 심었다(긴 세션에서 그 뒤 포커스/스크롤이 맨 위로 끌려가는 원인). → 본문 밖이면 `null`, 호출부는 복원을 건너뛴다. `0`(맨 앞)과 `null`(복원 대상 없음)을 같은 값으로 뭉개지 말 것.

- **편집 중(본문/번역칸 포커스) 재렌더는 재중앙하지 않고 픽셀만 지킨다.** — 재중앙은 브라우저가 커서에 맞춰 둔 스크롤을 빼앗아 모바일 키보드 위로 튕겨 올린다(`onResizeSettled`/`keepCaretVisible` 과 같은 판정). → `redrawBodyPreservingCaret` 은 `isEditingFocused()` 면 `rescueDroppedScroll` 만 태운다.

- **분기 패널(`BranchSection`)의 재렌더는 스크롤 위치를 담았다 되돌린다.** — `renderBody()` 가 `body.empty()` 로 다시 그려 노드 이동·카드 펼치기·즐겨찾기·외부 갱신마다 목록/지도가 맨 위(전체 보기는 좌상단)로 튀었다(2026-08-15 수정). → `captureScroll()`(지우기 직전) + `restoreScroll()`(즉시 + rAF 한 번 더). 지도 뷰포트는 가로·세로 둘 다. 기억을 버리는 경우는 `render(false)`(세션 전환/모드 전환/최초 로드)뿐이고, 최초 진입의 현재 노드 자동 중앙(`pendingAutoCenter`)이 복원보다 우선. 새 재렌더 진입점을 만들면 `renderBody()` 를 거치게 할 것.

- **"보던 지점"의 offset 은 재렌더 뒤 본문에 존재하지 않을 수 있다 — 위치를 못 찾으면 그 자리(재렌더 직후 scrollTop=0 = 맨 위)에 두지 않는다.** — 분기 이동(분기 패널 점프/형제 이동/undo·redo/본문 띠 되돌리기)은 본문이 짧아지거나 갈라져 보던 대목이 사라지는데, `charRectAtDisplayOffset` 이 null 을 돌려주고 `preserveReadingPosition` 이 폴백 없이(fallbackToEnd=false) 끝나 매번 맨 위로 튀었다(2026-08-15 수정). → (1) 끝을 넘어선 offset 은 본문 길이로 clamp 하고 앞뒤로 스캔, (2) `preserveReadingPosition` 의 **첫 시도만** 끝으로 폴백(이후 삽화 로드 재중앙은 폴백 없음), (3) `handleExternalChange`(외부발 재렌더)도 `preserveReadingPosition` 경유. 노드 앵커 복원(`restoreToAnchor`)은 앵커가 새 활성 경로에 남아 있을 때만 — 사라진 앵커면 무조건 맨 끝으로 끌고 가 preserve 결과를 덮는다.

- **집필 프로 변환 완료(`applyProConversionResult`)는 재중앙하지 않고 픽셀 스크롤을 그대로 유지한다.** — `preserveReadingPosition`(재중앙)을 쓰면, 아래로 내려가며 한국어판을 수정하던 사용자를 수정 지점이 화면 중앙에 오도록 위로 튕겨 올렸다(2026-07-21 수정). 변환은 보고 있는 화면 위쪽 높이를 바꾸지 않으므로 스크롤을 건드릴 이유가 없다. → 재렌더 앞뒤로 `activeScroller().scrollTop` 만 보존(번역 패널은 `renderTranslationBlocks` 가 자체 보존). 여기서 다시 `preserveReadingPosition` 으로 되돌리지 말 것.

- **인라인 삽화 위젯은 파괴/재생성하지 않고 풀(`inlineWidgetPool`)에서 DOM 이동으로 재사용한다.** — 매번 전부 지우고 다시 만들면 `<img>` 재로드로 높이 출렁임이 발생. → `renderInlineIllustrations` 는 안 바뀐 노드 위젯은 그대로 옮기고 `variantSig` 가 실제로 바뀐 노드만 캐러셀을 다시 그린다. 풀 비우기는 full `render()`(root.empty) 때만.

- **삽화 표시면(인라인/출력 뷰)은 "어느 노드를 그릴지"를 같은 기준으로 판단한다 — 각자 다른 규칙을 쓰면 같은 삽화가 두 화면에 갈라진다.** — 출력 뷰는 `pathToLeaf` 로 "경로에 삽화 있는 마지막 노드"를, 인라인은 `computeIllustrationAnchors` 로 "본문에서 그 노드가 차지한 구간"을 봤다. **본문 끝을 지운 직후 삽화를 만들면** 대상 노드가 `activeLeafId` = 그 `delete` 편집 노드라, 차지한 글자가 없어 인라인은 영영 안 그리고 출력 뷰만 그렸다 — 사용자에겐 "첫 삽화는 본문에, 재생성한 건 출력창에" 갈라져 보였고 출력창을 닫아도 안 돌아왔다(파일에 그렇게 저장된 상태라. 2026-08-19 수정). → 세 겹: ①붙일 때 `resolveIllustrationTargetNode` 가 글자를 안 남기는 리프를 피한다 ②그릴 때 자기 글자가 애초에 없던 노드는 그 편집 지점에 앵커를 준다(과거 데이터 구제. 글자를 썼다가 지워진 노드는 기존대로 미표시 — 이 구분을 없애지 말 것) ③출력 뷰도 `computeIllustrationAnchors` 의 마지막 항목으로 고른다. **삽화 표시면을 새로 만들면 노드 선택을 직접 짜지 말고 이 앵커를 쓴다.**

- **세션 본문에서 파생되는 모달은 `shouldRestoreSelection=false`.** — 옵시디언 Modal 기본값이 닫힐 때 이전 포커스/선택을 복원하는데, 거대 contenteditable 재포커스 스크롤로 최상단 점프가 났다. → 새 파생 모달은 `modal-shell.ts` `createModalShell` 을 쓰거나(일괄로 끔) 생성자에서 직접 끈다.

- **캐러셀 카운터는 텍스트 노드 대신 `data-count` 속성 + CSS `content` 로 그린다.** — 인라인 위젯은 텍스트 0글자 원자 블록이어야 본문 diff/offset/caret 이 안 오염된다. 텍스트 노드로 되돌리면 원문 편집 diff 가 깨진다.

- **본문(contenteditable) 안에 꽂는 위젯에 글자를 담지 않는다 — 텍스트가 필요하면 `data-` 속성+CSS `content` 또는 폼 요소의 `value`.** — 세션창은 `bodyEl.textContent` 를 **그대로** 편집 diff 기준(`syncPendingDiff`)으로 쓴다. 위젯이 텍스트 노드를 하나라도 가지면 그 글자가 본문으로 저장되고 offset 매핑까지 어긋난다. 세션 노트(QR `/comment`) 위젯이 긴 본문을 담아야 해서 걸린 문제 — 제목은 `data-title`+CSS `content`, 본문은 **readonly `<textarea>` 의 `value`**(자식 텍스트 노드가 아니라 `textContent` 에 안 잡히면서 선택·복사는 된다). 삽입 기준점을 찾는 루프는 공용 `isInlineWidgetNode`(삽화/노트/AI 시작 마커)로 위젯을 건너뛴다 — 위젯 클래스를 개별 루프에 손으로 나열하지 말 것.

- **세션창 상단 정보 헤더(썸네일/시나리오명/세션명/★)를 다시 만들지 않는다.** — 의도적으로 제거됨. 세션명·시나리오명은 사이드바와 탭 제목이, 즐겨찾기는 사이드바(세션)/하단 툴바(노드)가 담당. 뷰어 옵션 버튼은 본문 위 우측 상단에만 쌓는다(모바일=뷰 헤더 액션 / PC=같은 모양 플로팅 가로 줄, 버튼 구성·순서 1:1 유지).

- **세션 호스트 판별은 `isSessionHostView` 하나만 통과시킨다 (타입 + `getSessionFile` 존재 검사).** — 옵시디언 1.7+ 지연 로딩 탭(DeferredView)은 `getViewType()` 은 세션 뷰로 보고하지만 실제 메서드가 없어 "getSessionFile is not a function" 이 났다. 뷰 타입 문자열로 직접 거르는 코드를 새로 만들지 않는다.

- **세션창과 파생 표시(번역 보기 등)는 직접 편집이 기본 모드.** — 읽기 전용 표시, 별도 편집 버튼/모달/편집 모드를 만들지 않는다. 본문을 고치면 즉시 노드/variant 로 저장.

- **집필 프로 끝 접합에서 저자가 남긴 끝 줄바꿈(빈 줄)을 trim 으로 버리지 않는다.** — `convertAndSplice` 가 `ko.trim()`/토큰 재조립으로 초고 끝 줄바꿈을 잘라 매니스크립트가 줄바꿈 없이 끝났고, 뒤이을 생성/집필이 마지막 문단에 줄바꿈 없이 들러붙었다(특히 `***` 뒤). → append 텍스트는 `op.ko.match(/\n+$/)` 로 저자의 끝 줄바꿈을 그대로 이어 붙인다(없고 끝이 장면 전환이면 `\n` 한 줄). 끝-접합 전용, replace(중간 수정)는 대상 아님.

- **집필 프로 한국어 보기에서 편집 대상이 아닌 문단(장면 전환 `***`)은 `contenteditable=false` 원자 위젯으로 렌더한다.** — `***` 을 일반 편집 문단으로 두니 커서가 그 끝에 들어가 타이핑이 구분선에 병합됐고(→ `***안녕`), user-edit 로 잡혀 재변환되며 장면 전환이 파괴됐다. 사용자는 "뒤에 입력이 안 된다"고 느낌. → 구분자 span 과 동급으로 `contenteditable=false`(`.ggai-tr-scenebreak`) — 커서가 못 들어가 뒤 클릭 시 다음 편집 지점(대기영역)으로 넘어간다. 선택-삭제는 range/offset 기반이라 영향 없음.
