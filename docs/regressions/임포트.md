# 임포트 회귀 방지 규칙

> 이 영역을 수정할 때만 읽는다. 규칙은 실제 사고에서 얻은 불변식이며, 구현이 바뀌면 현재의 올바른 경로만 남도록 갱신한다.

- **임포트한 내용은 "세션을 만든 뒤 두 번째 저장으로" 채우지 않는다.** — 실리태번 채팅(.jsonl) 임포트가 빈 세션을 먼저 만들고(`createSession(seed="")`) 노드 트리를 메모리에만 심은 뒤 `saveSession` 으로 채웠다. 그 사이(활성 페르소나 해석, store 이벤트 리스너, 두 번째 쓰기)에서 무엇이든 던지면 **대화가 하나도 없는 빈 세션만 디스크에 남는다** — 사용자에겐 "임포트는 됐는데 세션이 텅 빔"으로 보인다(실제 잔해: 노드 1개·patches 0개·personaFile 없음). → `createSession(..., prefill)` 로 **노드 트리·활성 리프·페르소나를 생성 첫 쓰기에 함께** 넣는다. 실패하면 아무것도 안 남는 게 맞다(반쯤 만들어진 세션 금지). 파서/빌더는 무죄일 수 있으니(실제 파일로 검증됨) 같은 증상이 또 나오면 **쓰기 순서**부터 본다.
