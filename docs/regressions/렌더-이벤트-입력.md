# 렌더/이벤트/입력 회귀 방지 규칙

> 이 영역을 수정할 때만 읽는다. 규칙은 실제 사고에서 얻은 불변식이며, 구현이 바뀌면 현재의 올바른 경로만 남도록 갱신한다.

- **좌우 사이드바가 세션 트리를 바꾸기 전에 열린 편집과 진행 중 작업을 확인한다.** — 우측 분기 이동·하위 삭제가 세션창의 미저장 본문/번역을 flush하지 않고 공유 세션 객체의 `activeLeafId`·노드 트리를 바로 바꾸면 편집이 취소되거나 생성 중 노드를 삭제할 수 있다. 제목 변경 때 `setViewState`로 탭을 다시 만들면 커서·스크롤·초안도 사라진다. → 분기 조작·제목 변경은 `plugin.prepareSessionTreeChange`/`plugin.renameSession` 경유, 초안 저장은 `flushSessionEdits(..., { convert:false })`, 생성·변환 중에는 중단. 이름 변경은 `session-renamed` → `SessionHostView.retargetSessionFile`로 경로만 바꾸고 DOM·공유 객체를 유지한다.

- **세션 저장 실패를 완료로 취급하거나 삭제된 파일을 늦은 저장으로 되살리지 않는다.** — 디스크 부족·동기화 오류 뒤 화면에는 생성 결과가 남아도 저장되지 않았는데 자동 번역·삽화·다음 발화가 계속 돌면 재실행 때 결과가 사라지고 파생 데이터만 남는다. 파일별 쓰기가 겹치면 오래된 저장이 우측 설정을 되돌릴 수도 있다. → `StellaStore`의 `WriteQueue`로 직렬화하고 실패한 최신 쓰기를 공유 객체 기준으로 재시도한다. 실패 중 `refreshSession`은 캐시를 유지하며, 결과 저장 성공 전에는 생성 완료 확장을 실행하지 않는다. 기존 파일이 없는 일반 저장은 create로 복구하지 않는다(신규 생성은 `createSession` 전용).

- **`suppressOwn*` 수동 억제 플래그를 다시 만들지 않는다.** — 뷰마다 손으로 억제 플래그를 관리하다 누락·중복 렌더가 반복됐고 2026-07 재렌더 개편으로 전면 폐기됨. → `store.saveSession(file, session, { kinds, origin })` detail 방식: 핸들러가 `detail?.origin === this.storeOrigin` 이면 자기 에코 skip, `kinds:["settings"]` 면 국소 갱신만. 번역/삽화 저장·서비스(opts.origin)도 동일.

- **편집 UI 재렌더 가드를 손으로 복붙하지 않는다.** — 복사할 때마다 조합/포커스/자기저장 가드가 한 조각씩 빠져 "입력 포커스 소실"이 반복 재발했다. → 공용 `src/views/edit-guard.ts` `EditGuard` 만 사용: 이벤트 핸들러 첫 줄에서 `isSavingSelf`/`isEditing()` 확인, 저장은 `runSave()`, 포커스 중·조합 중·pending 편집 존재 시 textarea 외부 덮어쓰기 금지. IME 조합 중 input 을 무시하는 필드는 반드시 `compositionend` 에서 확정값을 onChange 로 넘긴다(마지막 글자 유실 방지). store 쪽 `SELF_WRITE_GRACE_MS`(2000ms) 방어와 겹으로 유지.

- **한글 IME 조합 중 배경 뷰가 본문 DOM 이나 문서 선택영역을 건드리지 않는다 (입력 마비 사고).** — 어느 입력칸에서든 조합 진행 중에 배경 세션창이 DOM/`Selection` 을 만지면 Chromium 이 조합을 얼린다(커서 소실 + 키 전부 삼킴, 창 전환해야 풀림). 메모리/작가노트 등 디바운스 저장이 쏜 이벤트를 배경 세션창이 받아 본문을 손대는 경로가 원인이었다. → `edit-guard.ts` 전역 트래커(`installGlobalImeTracker`/`isImeComposing`/`runWhenImeIdle`) + 세션창 `deferWhileComposing`(외부 변경/매크로/번역/인라인 위젯 재배치를 조합 종료 뒤로 코얼레싱). `setCaretOffset` 은 다른 편집칸이 포커스면 선택영역을 건드리지 않는다. 배경에서 contenteditable 재렌더/선택영역 조작 코드를 새로 넣을 때 반드시 이 게이트를 태운다.

- **명시적 액션(이어쓰기/재생성/undo/redo/미리보기 flush)은 조합 중이라도 편집을 강제 커밋한다 (입력 롤백 사고).** — 세션창 `commitPending()` 은 IME 조합 중 `body.empty()` 재구성이 조합을 얼리므로 커밋을 미룬다. 그런데 이 지연을 호출자가 몰라, 조합 중 마지막 음절이 미커밋인 채 이어쓰기가 진행돼 **입력 전 노드에서 생성이 시작되고 방금 친 내용이 롤백**됐다(한글 사용자, 조합 중 클릭). → 순수 타이핑 hot-path(blur/idle/selectionchange)만 미루고, 편집을 확정하고 진행하는 명시적 액션은 `commitPending({ force: true })` 로 조합을 강제 종결(`composing=false` + `syncPendingDiff` 로 DOM 의 진행 중 조합 문자열까지 캡처)한 뒤 커밋한다. 생성·미리보기·형제이동 전 flush 는 전부 force 경로.

- **편집 확정을 `blur` 단독에 걸지 않는다 (모바일 이름 유실 사고).** — 모바일 웹뷰는 입력칸이 화면에서 사라질 때(OS 뒤로가기·탭/세션 전환·앱 백그라운드·제스처 이동) `blur` 를 신뢰성 있게 쏘지 않는다. 프롬프트 세트/항목 이름을 고치고 blur 없이 벗어나면 저장이 아예 안 일어나 개명이 유실됐다(제보: "수정 후 확인하니 그대로"). 프롬프트 편집기만 유독 ① 글자마다 저장 안 함 ② dispose flush 없음 ③ 앱 전환 flush 없음 — blur 하나에 전부 걸려 제일 잘 터졌다. → **모델 반영은 `input`(글자마다)에서** 하고 저장은 debounce, 확정은 blur **와 함께** dispose·`visibilitychange(hidden)`·`window blur` 에서도 flush. 공용 `renderEditableTitle`(제목)은 라이브로 모델에 넣고(재렌더 금지 — 입력 파괴), `form-renderer` 필드와 같은 방식. detail-view 처럼 외부발 refresh 가 입력칸을 재렌더로 날리는 섹션(`PromptsSection`)은 타이핑 중엔 저장하지 말고 모델만 갱신, 저장은 blur/`flush()` 에서만(호스트가 5개 flush 지점에서 호출). 새 편집 UI 를 넣을 때 "blur 에서만 저장" 패턴을 다시 만들지 말 것.

- **작성 중인 입력값을 DOM 에만 두지 않는다 (폰 SNS "사진만 올라감" 사고).** — 폰 SNS 작성칸은 `textarea.value` 가 유일한 저장소인데 첨부(`pendingAttach`)는 필드였다. 그래서 **글을 쓴 뒤 사진을 첨부하면**(첨부 미리보기 = `renderBody()`) 글만 지워지고 사진은 살아남아, 사용자가 [게시]를 누르면 **그림만 올라갔다**. 번역·SNS 생성이 끝나 피드 이벤트가 오는 순간에도 같은 일이 났다 — 재렌더 보류 가드(`isSnsComposing`)가 **포커스+내용**을 함께 요구해, 사진 피커 모달이 포커스를 가져간 뒤에는 가드가 풀려 있었다. → **초안은 필드가 진실 소스**(`snsDraft`/`replyDraft`): `input` 마다 필드에 넣고 렌더 때 `ta.value = draft` 로 되살린다(전송 시 비움, 다른 글의 답글칸으로 옮기면 리셋). 포커스 기반 재렌더 가드는 "타이핑 중 깜빡임 방지"용 보조일 뿐, 데이터 보존을 여기에 걸지 않는다. 새 작성 UI 를 넣을 때 입력값이 재렌더를 넘어 사는지부터 확인할 것(문자 작성칸은 `buildComposer` 로 body 밖에 한 번만 만들어져 애초에 안전).

- **세로 flex 목록의 항목에 `overflow: hidden` 을 줄 때는 `flex: 0 0 auto` 를 함께 준다 (SNS 카드 뭉개짐).** — 피드 카드에 사진 풀블리드용 `overflow:hidden` 만 넣었더니 카드들이 납작하게 눌려 서로 겹쳤다. flex 항목의 자동 최소 크기(`min-height:auto` = 내용 높이)는 **overflow 가 visible 이 아니면 0 이 된다** — 스크롤 컨테이너 안에서도 항목이 무한히 줄어든다. → 내용 높이를 지켜야 하는 항목은 `flex: 0 0 auto`(칩 바가 이미 같은 이유로 고정돼 있었다). 새 카드/행에 overflow·clip·scroll 계열을 넣을 때 항상 짝으로 확인.

- **접힘/숨김 상태를 `hidden` 속성으로 만들지 않는다 — 우리 CSS 가 그 요소에 `display` 를 주는 순간 무력화된다.** — 세션 노트 위젯(QR `/comment`)이 `body.hidden = true` 로 접었는데 `.ggai-note-body { display: block }` 이 브라우저 기본 `[hidden] { display: none }` 을 이겨(작성자 스타일 > UA 스타일, 옵시디언 app.css 에도 `[hidden]` 규칙 없음) **한 번도 접힌 적이 없었다**. 접힌 상태에선 textarea 기본 높이(2줄) + `overflow:hidden` 이라 본문이 잘려 보이고 눌러도 변화가 없어 "잘린다 / 안 접힌다"로 제보됐다(2026-07-31 수정). → 표시 상태는 **클래스 하나**(`.is-open`)가 진실 소스이고 `display` 는 CSS 가 소유한다. `hidden` 속성이나 `el.hide()`(인라인 스타일)로 상태를 표현하지 않는다. 곁가지 둘: 접이식 본문 높이를 픽셀로 고정하면(autosize) 폭이 바뀔 때 잘리므로 `ResizeObserver` 로 폭 변화 때 다시 맞춘다. 챗 뷰는 재렌더마다 `host.empty()` 로 다시 그리므로 노트 위젯도 삽화처럼 **풀에서 재사용**해야 펼쳐 둔 게 안 접힌다.

- **스트리밍 중 이미 그린 것을 지우고 다시 그리지 않는다 (생성 중 버벅임·메모리 폭증·스크롤 튐 사고).** — `renderStreamingTail` 이 조각(delta)마다 `container.empty()` 후 그때까지의 생성분 전체를 글자 단위로 다시 만들었다. ① 비용이 **생성 길이의 제곱** — 3000자 생성이면 옛 방식 112만 자 재생성 vs 새 방식 2.4만 자(47배), 8000자면 125배. 버려진 DOM 이 GC 전까지 쌓여 메모리가 치솟고 옵시디언 밖까지 끊겼다. ② 지우는 순간 tail 높이가 0으로 무너져 브라우저가 `scrollTop` 을 강제로 clamp — 다시 채우면 튕겨 돌아오는 **초당 수십 번의 위아래 떨림**이 "생성 중 화면이 위로 딸려 올라간다"의 정체였고, 흔들리는 높이를 읽는 `isNearBottom` 도 오판해 읽으려 올린 화면이 바닥으로 끌려갔다. → **덧붙이기만 한다**: 줄바꿈이 지나간 줄은 굳히고(`streamTailCommitted`) 쓰고 있는 마지막 한 줄만 다시 그린다(`planStreamTail`). 그리기 자체는 `scheduleStreamPaint` 로 **한 프레임에 한 번** — 조각마다 그린 뒤 `scrollHeight` 를 읽으면 브라우저가 모아 처리하려던 레이아웃을 매번 강제로 끊어 쓴다(세션 전체가 문단 없는 인라인 한 덩어리라 그 비용이 세션 길이에 비례한다). 새 스트리밍 표시 경로를 넣을 때 "매번 전부 다시 그리면 안전하다"를 다시 고르지 말 것 — 안전한 대신 길이의 제곱으로 터진다.

- **UI 동기화를 통짜 재렌더로 해결하지 않는다.** — 원칙이지만 반복 위반됐다. → store 이벤트 받아 자기가 표시하는 값만 국소 갱신, 스크롤·접힘·포커스·편집 중 값 보존. 전체 렌더는 DOM 소유권이 실제로 바뀔 때만.

- **목록 표시용 재스캔은 이미 캐시된 세션 객체를 건드리지 않는다 (설정 롤백 → 생성 노드 삭제, 두 번 터진 사고).** — 1차(설정 롤백): `refreshSessions()` 가 `sessionByFile` 항목을 새 객체로 **교체**해 열려 있는 SessionView 의 `this.session` 이 캐시에서 떨어져 나갔고, 디테일 뷰에서 바꾼 모델/파라미터/프롬프트/번역 설정이 다음 생성 때 세션창의 **옛 사본** 저장으로 직전 값으로 롤백됐다. 이를 `assignSessionInPlace(existing, fresh)` **제자리 덮어쓰기**로 막았더니 2차(생성 노드 삭제): 사이드바에서 시나리오를 펼쳐 두면 생성 저장마다(자기 에코도 안 거름) `session-changed` → `refreshSessions` → `scanSessions`(디스크 직접 `adapter.read`) → 활성 세션 객체를 **아직 flush 안 된 stale 디스크로 덮어써**, 방금 붙은 생성 노드가 세션창 메모리에서 삭제되고 이후 저장이 그 빈 상태를 굳혀 JSON 에서도 사라졌다(화면엔 1~2초 떴다 사라짐, 로그엔 있는데 JSON 엔 없음, 소설·챗 공통, 간헐적, 동기화 무관·새 볼트도 재현). → **목록 재스캔은 캐시 객체를 교체도 덮어쓰기도 하지 않는다**: `existing` 이 있으면 `item.session = existing` 로 그 최신 객체를 목록에 쓰기만 한다(`getSessions` 의 "이미 있으면 안 덮어씀" 과 동일 정책). 목록은 meta(이름/즐겨찾기/시각) 표시용이라 세션 본문 객체를 소유·수정할 이유가 없다. 활성 세션 객체의 갱신은 저장 경로(`saveSession`)와 외부 변경 반영 경로(`refreshSession` 단수, self-write grace 적용)만 맡는다. **"공유해놓고 가드로 막기"가 아니라 애초에 목록이 활성 객체를 공유하지 않는 게 정답.**

- **창 포커스 복귀발 `refreshSession` 이 방금 저장한 세션을 stale 디스크로 덮어쓰지 않는다 (생성 유실 사고).** — 이어쓰기를 걸고 창을 벗어난 사이(알림음이 그 증거 — 안 보는 세션만 울림) 백그라운드에서 생성이 끝나 `session.json` 저장이 시작되는데, 이때 `this.generation` 은 이미 `null`. 돌아오는 순간 window `focus` → `handleExternalChange` → `refreshSession` 이 **디스크를 강제로 다시 읽어** 캐시를 덮어쓴다. 동기화 폴더/느린 디스크에선 `vault.modify` 가 아직 안 내려가 옛 내용을 읽고, 방금 받은 노드가 메모리에서 사라져 세션뷰·분기에서 증발했다(로컬 SSD 는 창이 좁아 거의 안 걸려 재현이 특정 환경에서만 남). 디스크엔 대개 정상 저장돼 있어 세션을 닫았다 열면 되살아남. → `refreshSession` 은 `isRecentSelfWrite(file)` 이면 디스크 재읽기를 건너뛰고 캐시를 반환한다(`onVaultChange` 와 동일한 `SELF_WRITE_GRACE_MS` 규칙). 창/가시성 복귀처럼 vault 이벤트를 안 거치는 재읽기 경로를 새로 넣을 때 반드시 이 self-write grace 를 태운다.

- **디스크 재읽기는 "메모리가 디스크보다 새로우면" 절대 덮어쓰지 않는다 — modifiedAt 불변식 (우측 디테일뷰발 생성 유실 사고, 위 두 사고의 최종 봉쇄).** — 생성은 새 노드를 메모리에만 추가하고 저장은 종료 후라, 생성이 도는 수십 초 동안 디스크는 항상 메모리보다 옛날이다. 이 사이 어떤 경로든(우측 디테일뷰 시나리오 탭 로드 `resolveActive`, 창 포커스 복귀 `refreshVisibleSectionsFromDisk` 등) `refreshSession` 이 돌면 2초 self-write grace 는 이미 지나 있어 공유 세션 객체가 노드 없는 디스크본으로 덮여 생성이 통째로 사라졌다(제보: 이어쓰기 중 우측 패널을 클릭만 해도 실패 — 트리거는 화면 상태 의존이라 재현이 갈렸다). → `refreshSession` 은 디스크 `modifiedAt <= 메모리 modifiedAt` 이면 캐시를 그대로 반환한다. 자기 저장은 `saveSession` 이 호출 즉시 캐시 객체의 modifiedAt 을 올려 항상 메모리 ≥ 디스크이고, 진짜 외부 변경은 `onVaultChange` 가 캐시를 지워 비교 자체를 안 거친다(fresh 경로). **개별 트리거를 쫓아 가드를 덧대지 말 것** — "오래된 디스크로 새 메모리를 덮지 않는다"는 이 한 줄이 그 클래스 전체를 닫는다. 새 디스크 재읽기 경로를 추가해도 이 불변식 아래에서는 안전하다.

- **활성 설정을 "못 찾았으니 기본값으로" 조용히 덮어쓰지 않는다.** — `PromptsSection` 이 세션의 `promptSetId` 를 목록에서 못 찾으면 목록 첫 세트를 활성으로 **저장**해, 세트 이름 변경·삭제·레거시 필드 세션의 프롬프트가 사용자 모르게 갈아끼워졌다. → 자동 지정은 값이 **아예 없을 때만**. 지정돼 있는데 해석 실패면 표시만 비우고 저장은 건드리지 않는다.

- **편집면(`contenteditable`)의 속성을 직접 `setAttr` 하지 않는다 — 모바일 탭 게이트가 소유한다.** — 본문·번역칸·말풍선이 항상 편집 가능하게 깔려 있어, 모바일에서 스크롤하고 손을 떼면 브라우저가 그 자리에 caret 을 놓아 키보드가 올라왔다(제보: "스크롤할 때 입력바가 활성화된다"). → `src/util/tap-to-edit.ts` `attachTapToEdit(el)` 이 평소엔 속성을 떼 두고 **제자리 짧은 탭**(이동 8px·700ms 이내, 스크롤 후 300ms 정적)에만 되돌려 붙인 뒤 포커스 + 탭 지점 caret 배치를 한다(데스크톱은 게이트 없음 — 값만 기억). 그래서 이 요소들의 contenteditable 은 게이트가 소유한다: 생성 중 잠금 같은 "편집 금지"는 `setEditAllowed(el, false)`, 재렌더 뒤 포커스 복원과 메뉴발 편집 진입은 `beginEdit(el)`(속성이 떨어져 있어도 되살린다). 직접 `setAttr("contenteditable", …)` 로 되돌리면 게이트가 풀려 스크롤 오인이 그대로 재발하고, 반대로 `focus()` 만 부르면 잠긴 요소라 포커스가 안 잡혀 "입력이 씹힌다"로 나타난다. 편집이 잠긴 동안에도 글자 선택이 되도록 해당 요소에 `user-select: text`(+`-webkit-`)를 명시할 것.

- **읽는 화면을 편집칸으로 깔아 두지 않는다 — 누를 것이 있는 화면은 읽기가 기본이다.** — 챗 말풍선이 항상 `contenteditable` 이라 **탭 = 편집 진입**이었다. 그래서 (1) 카드가 그린 상태창·표를 누르면 화면이 HTML 원문 글자로 튀어나오고 (2) 링크·접기(`details`)·이미지·선택지 버튼처럼 **눌러야 동작하는 것이 전부 죽었다**(캐럿만 놓인다) (3) 모바일에서 읽다가 오탭하면 키보드가 올라왔다. 탭 게이트(`tap-to-edit`)는 (3)만 덮는 증상 처치였다. → 편집 진입은 **명시적 버튼**으로만 연다(실리태번 `.mes_edit` 과 같은 구조): 열린 하나만 편집칸이 되고 나머지는 표시본 그대로다. 판정 상태(`editing`)를 뷰가 들고 있어야 한다 — DOM 포커스로만 "편집 중"을 판정하면 편집칸을 닫은 뒤에도 포커스가 남아 재렌더가 통째로 미뤄진다. blur 는 커밋만 하고 닫지 않는다(다른 곳을 눌렀다고 편집이 사라지면 안 된다). 표시 계층에 **누를 수 있는 것을 새로 넣을 때마다** 그 위가 편집칸인지 먼저 본다.

- **읽는 글 위의 롱프레스를 우리 메뉴가 가져가지 않는다 — OS 단어 선택(사전/웹 검색)이 거기 걸려 있다.** — 말풍선 전체에 롱프레스 메뉴를 붙여, 모바일에서 단어 하나를 골라 복사하거나 사전에 넣는 것이 아예 불가능했다(제보: 영어 공부하며 노는 사용자). **코드로 만든 선택에는 iOS·안드로이드 둘 다 기본 메뉴를 띄워주지 않으므로**("단어를 대신 선택해 주기"로는 해결되지 않는다) 제스처 자체를 OS 에 넘겨야 한다. → `press-menu.ts` `attachContextMenu(..., { yieldToTextSelection: true })`: 모바일에서 **손가락이 글자 위에 떨어졌으면** 우리 메뉴를 띄우지 않는다(롱프레스 타이머 + 안드로이드의 `contextmenu` 경로 **둘 다** — 후자에서 `preventDefault()` 하면 OS 선택 메뉴까지 사라진다). 판정은 타이밍이 아니라 위치다(`pointIsOverGlyph` — caretRangeFromPoint 는 여백에서도 가장 가까운 글자를 돌려주므로 그 글자의 사각형이 좌표를 품는지까지 본다). OS·버전마다 롱프레스 임계값이 달라 타이밍으로 가르면 폰마다 동작이 갈린다. 글자를 OS 에 넘긴 만큼 **메뉴를 부를 글자 없는 자리**(아바타·이름줄)를 같이 열어둘 것 — 안 그러면 메뉴가 사실상 사라진다.
