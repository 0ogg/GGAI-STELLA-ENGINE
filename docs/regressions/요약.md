# 요약 회귀 방지 규칙

> 이 영역을 수정할 때만 읽는다. 규칙은 실제 사고에서 얻은 불변식이며, 구현이 바뀌면 현재의 올바른 경로만 남도록 갱신한다.

- **요청 1번 = 앵커 1개.** — 한 구간을 몰래 여러 요청으로 쪼개 결과를 앵커 하나로 합치는 릴레이 배치는 "요청이 끝났는데 카드가 안 뜨는" 블랙박스였고 폐기됨. 구간이 입력 한도를 넘을 것 같으면 요청을 나누지 말고 `planSummaryBoundaries` 의 maxChars 로 **앵커 경계를 더 잘게** 나눈다. 요청 하나가 끝나면 앵커 하나가 즉시 저장·표시, 진행 n/m = 실제 요청 수 = 카드 수. 별도 체크포인트 없음(`summaries.pending` 은 deprecated, 발견 시 삭제만).

- **요약 재생성 시 직전 앵커 탐색에서 대상 노드 자신의 앵커를 제외한다.** — 제외하지 않으면 자기 앵커가 "직전 요약"으로 잡혀 새 패시지가 항상 0 → 재생성이 영원히 skip 되는 버그(2026-07-04 수정). `summarize()` 의 `prior = chain.filter(a => a.nodeId !== target)`, recentEvents 도 동일.

- **"매크로를 썼으니 자동 삽입 생략" 판정은 매크로가 확장되는 자리 전부를 본다.** — `{{summary}}` 배치 판정(`summaryExplicit`)이 프리셋 **텍스트 항목만** 훑어서, 작가노트·세션 메모·마커 가공 템플릿(wrap)·로어북 항목·본문에 쓴 `{{summary}}` 는 배치로 안 쳐줬다. 매크로는 그 자리에서 확장되는데 자동 삽입도 그대로 돌아 **같은 요약이 두 번** 들어갔다(사용자에겐 "위치를 옮기는 게 아니라 하나 더 붙는" 것으로 보임, 2026-08-13 수정). → `summaryMacroTexts()` 로 확장 대상 원문을 모아서 판정한다. 새 매크로 확장 지점(새 필드·새 wrap)을 추가하면 이 목록에도 넣는다. **같은 모양의 판정이 페르소나(`presetUsesPersonaMacro`)에도 남아 있다** — `{{persona}}` 를 wrap/작가노트 등에 쓰면 페르소나가 두 번 들어간다.
