# 타입/기타 회귀 방지 규칙

> 이 영역을 수정할 때만 읽는다. 규칙은 실제 사고에서 얻은 불변식이며, 구현이 바뀌면 현재의 올바른 경로만 남도록 갱신한다.

- **`.catch(() => [])` 폴백은 반환 타입을 명시한다: `catch((): T[] => [])`.** — 타입 미지정 시 union 축소 캐시 순서가 바뀌어 **다른 파일**의 같은 패턴이 never 로 깨진 실사례(entity-actions → chat-session-view).

- **`onunload` 에서 `detachLeavesOfType()` 을 호출하지 않는다.** — 옵시디언 공식 가이드의 안티패턴(사용자 레이아웃 파괴).

- **"자동 실행 스위치"에 수동 기능 UI 를 묶지 않는다.** — 폰 번역 설정을 토글 하나로 간소화하면서 뷰의 `phoneTranslationEnabled()` 를 `isAutoTranslateOn()`(자동 번역 스위치)로 연결했다. 그 결과 자동 번역을 끄면 **번역 보기·원문 보기·개별 번역 재생성 같은 수동 기능이 메뉴에서 통째로 사라졌다**(설정만 줄이라고 했는데 기능이 없어짐, 2026-07-26 사고). 자동/수동은 별개 축이다: 자동 스위치는 "생성 후 알아서 번역할지"만 정하고, **수동 조작은 항상 노출**한다(사용자가 직접 누르는 건 언제나 가능해야 한다). 설정 항목을 줄일 때 그 값이 UI 노출 조건으로 쓰이고 있는지 먼저 `grep` 한다.

- **폰 오버레이는 `.modal` 자체 크기를 폰 루트와 같게 못박는다.** — 옵시디언 기본 `.modal` 은 `max-height: 80vh` + `overflow: auto` 인데 폰 루트(`.ggai-phone-modal .ggai-phone-root`)는 `height: min(780px, 88vh)` 였다. 창 높이가 886px 미만이면 vh 갈래가 이겨 **루트가 모달보다 8vh 크고**, 모달이 스크롤 컨테이너가 되어 **폰 프레임 바깥에 스크롤바**가 생겼다(안쪽 본문 스크롤과 겹쳐 "이중 스크롤"). 설정 화면처럼 내용이 긴 화면에서 특히 눈에 띄었을 뿐 **모든 화면에 있던 상시 버그**다(2026-07-26 수정 — 재현 HTML 로 `.modal` 이 스크롤러임을 실측해 확정). → `.modal.ggai-phone-modal` 에 루트와 **같은 `height`/`max-height`** 를 주고 `overflow: hidden`. 폰 프레임 크기를 바꿀 땐 두 곳을 같이 바꾼다. **증상이 "프레임 바깥 스크롤"이면 안쪽(body/pane)을 고치지 말고 모달·루트의 높이 관계부터 실측한다.**

- **디테일 뷰 설정 컨트롤을 폰 화면 안에 그대로 가져다 쓰면 깨진다.** — 폰은 테마 오염을 막으려고 `.ggai-phone-root .ggai-phone-screen :where(button)` 로 버튼 꾸밈(테두리·배경·패딩·반경)을 전부 지운다. 설정 앱(폰 홈)에 컨트롤 킷을 얹었더니 `ggai-preset-btn`/`ggai-model-btn` 이 납작해져 설정 화면이 깨져 보였다(2026-07-26 수정). → 리셋과 **같은 특이도(0,2,0)** 의 `.ggai-phone-screen .클래스` 규칙을 파일 **뒤쪽**에 두어 되살린다(문서 순서로 이김). 값은 디테일 뷰 원본과 동일하게 유지해 두 화면이 같은 모양이 되게 한다 — 폰용으로 새 디자인을 만들지 않는다. 폰에 새 설정 컨트롤을 얹을 때마다 이 복원 목록에 추가했는지 확인.

- **폰 화면 안의 버튼 꾸밈은 클래스 하나(0,1,0)로 주면 리셋에 먹힌다 — `.ggai-phone-screen` 접두 필수.** — SNS 리스트 칩(`.ggai-phone-sns-listchip`)이 테두리·배경·패딩을 클래스 하나로만 줘서 테마 격리 리셋(`.ggai-phone-root .ggai-phone-screen :where(button)`, 0,2,0)에 전부 지워졌고, 칩이 맨 글자로 뭉개져 리스트 줄이 깨져 보였다(2026-07-26 발견 — `.is-active` 는 (0,2,0)이라 활성 칩만 멀쩡해서 오래 안 보였다). 폰 안에 버튼 모양을 새로 만들 때는 **반드시 `.ggai-phone-screen .클래스`** 로 쓴다(설정 컨트롤 복원 목록과 같은 규칙).

- **모바일 툴바 여백은 `env(safe-area-inset-*)` 직접 사용**(옵시디언 `var(--safe-area-inset-bottom)` 는 환경에 따라 0). 키보드에 가린 커서는 `visualViewport` 로 키보드 위까지만 스크롤.

- **엔진 onLayoutReady 끝에서 `window` CustomEvent `ggai-stella-engine-ready` 를 반드시 쏜다.** — 이걸 지우면 BRAT/hot-reload 로 엔진만 리로드됐을 때 새 엔진이 휴면으로 시작하고 옛 인스턴스의 설정 패널·라우팅이 통째로 사라져, 의존 플러그인(개인 PRO)이 새 엔진에 재배선할 트리거를 잃는다(개인 플러그인을 껐다 켜야 복구). onLayoutReady 는 리로드 시 즉시 재실행되므로 신호도 즉시 나간다. 의존 플러그인 쪽은 자기 소유 `registerDomEvent(window, ...)` 리스너로 받아 `connectEngine`(idempotent: 옛 배선 teardown 후 재활성화)을 돌린다.

- **SNS 데이터는 `feed.posts` / `accounts.accounts` 를 통짜로 읽지 않는다 — 반드시 활성 서버 필터를 거친다.** — 스텔라 네트워크 리스트는 V3-7 부터 **서로 단절된 별개 서버**다(글·계정에 `listId` 도장). 새 코드가 원본 배열을 그대로 순회하면 다른 서버의 글·주민이 피드·알림·프롬프트·세션 주입에 새어 들어가고, 사용자가 리스트를 나눈 목적(세션별 지식 격리)이 조용히 무너진다 — 화면은 멀쩡해 보여서 발견이 늦다. 읽기는 `phone.snsPostsOfActiveList(feed)` / `phone.snsAccountsOfActiveList(accounts)`, 세션 쪽 게이트는 `phone.isSessionInActiveServer(session)`, 쓰기는 생성 시점의 `phone.activeSnsListId()` 로 스탬프. id 로 한 건을 집는 경로(좋아요·답글·번역·삭제)는 예외 — 화면에 보이는 것만 집을 수 있으므로 필터가 필요 없다.

- **"정리용 후보 목록"을 자격 게이트로 만들지 않는다 — 판정 조건은 화면에도 적는다.** — 폰 연락처 후보를 `session.meta.personaFile`(세션당 페르소나 **하나**, 나중 선택이 덮어씀) 하나로 판정했다. 그래서 플레이 도중 페르소나를 바꾸면 그 캐릭터가 옛 페르소나 폰에서 **사라지고** 새 페르소나로 옮겨 갔고, 페르소나 기록이 없는 옛 세션은 어느 계정에도 안 떴다 — 유저에게는 "지금 대화 중인 캐릭터는 없고 엉뚱한 캐릭터가 뜨는" 무작위 동작으로 보였다(2026-08-25 제보). 이런 목록의 목적은 **많아서 헷갈리는 걸 줄이는 정리**이지 참가 자격 심사가 아니다 → 판정은 넉넉하게(이력을 **추가만** 하며 누적, 기록 없음 = 배제 아니라 통과), 좁히는 건 사용자가 직접 하는 등록/체크 단계에 맡긴다. 그리고 남는 조건 하나(여기선 폰 로그인 계정)는 목록·빈 화면 문구에 **계정 이름과 함께 적어** 유저가 규칙을 추측하지 않게 한다. 페르소나·계정 참조는 **경로가 아니라 id** 로 남긴다(이름 변경에 강건).

- **한 세션에 쓰기 주체가 둘 이상 붙을 수 있게 만들었으면, 겹침 방어를 그 자리에서 함께 만든다.** — 선채팅은 원래 `isViewingSession` 으로 "보고 있는 세션엔 안 끼어든다"고 판정했다. 이 판정을 사용자 요청으로 제거했더니(v0.0.38, "보고 있어도 온다"), **그게 겸사겸사 맡고 있던 겹쳐 쓰기 방어까지 같이 사라졌다** — 사용자가 말풍선을 고치는 중이거나 세션창이 스트리밍 중인데 백그라운드 서비스가 같은 세션 객체(store 캐시는 뷰와 **같은 참조**다)에 노드를 붙이고 저장한다. 게다가 `sendInner` 는 발화 직전 `flushSessionEdits` 로 **열린 세션창의 편집을 강제 커밋**시키므로, 사용자가 문장을 지우는 한복판에 저장이 끼어든다. → 판정 하나를 지울 때 그 판정이 **부수적으로** 지키던 불변식이 뭐였는지 먼저 적는다. 겹침 방어는 `session-host.ts` 의 `isSessionGenerating` / `isSessionBeingEdited` 로 명시한다: 스케줄러 틱은 바쁜 세션을 **건너뛰되 예약(nextAt)은 그대로 둬** 손을 떼면 다음 틱에 바로 오게 하고(예약을 미루면 요청받은 동작이 사라진다), `tick()` 에서 걸러 바쁜 세션 하나가 다른 세션의 차례까지 막지 않게 한다. 모델 응답을 기다리는 몇 초 사이에도 생성이 시작될 수 있으므로 **저장 직전에 한 번 더** 확인한다.
- **NAI 캐릭터별 프롬프트(`char_captions`)는 "글만" 보내면 500 이 난다.** — 삽화 프롬프트의 `|` 를 캐릭터별 프롬프트로 나눠 보내자마자 이미지 생성이 전부 500 으로 죽었다. 실제 NAI 산출물 PNG 메타데이터를 뜯어 보니 공식 클라이언트는 좌표를 **안 쓸 때도**(`use_coords:false`) 캐릭터마다 `centers`(우리 기본값은 인원수만큼 가로 균등 배치)를 넣고, `v4_negative_prompt.caption.char_captions` 를 **같은 길이·같은 좌표**로(캐릭터 UC 가 없으면 빈 문자열) 맞춰 보낸다. → 보정은 Core `providers/novelai.ts` 가 한다(플러그인은 `charCaptions` 만 넘기면 됨). `use_coords` 자동 판단은 **호출자가 준 좌표**만 세고 이 기본 좌표는 세지 않는다. 남의 API 페이로드는 문서가 아니라 **실제로 나간 요청/산출물 메타데이터**를 기준으로 맞춘다.
