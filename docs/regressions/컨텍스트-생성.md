# 컨텍스트/생성 회귀 방지 규칙

> 이 영역을 수정할 때만 읽는다. 규칙은 실제 사고에서 얻은 불변식이며, 구현이 바뀌면 현재의 올바른 경로만 남도록 갱신한다.

- **이스케이프 해제를 매크로 치환 **앞**에서 하지 않는다 (QR 카드 내보내기 오염).** — QR 파서가 `\|` 과 함께 `\{` `\}` 까지 풀어버려, 그 뒤 실행기의 매크로 치환이 `{{user}}` 를 진짜 페르소나 이름으로 바꿔버렸다. 카드 JSON 내보내기가 매크로 대신 이름이 박힌 파일을 만들어 다른 사람이 쓸 수 없는 카드가 된다(증상은 조용함 — 파일은 멀쉬하게 나온다). → 파싱은 `\|` 만 푸고(`unescapeQr` — 파이프 분리에 필요), 브레이스는 **치환을 끝낸 뒤** `unescapeQrBraces` 가 푸는다(실행기 `expand` 한 자리). 이스케이프는 "이 글자를 해석하지 말라"는 뜻이니, 해석기보다 먼저 풀면 지켜야 할 것을 지켜주지 못한다.

- **on/off 인자를 `true|1` 로만 받지 않는다 (QR 주입 영구화 사고).** — `/inject … ephemeral=on` 을 못 알아듣고 **지속 주입**으로 처리해, 버튼을 한 번 누르면 이후 모든 생성에 그 지시가 계속 따라붙어 세션이 오염됐다(실물 짱돌이 QR 이 `on` 을 쓴다). → 공용 `isQrFlagOn` 으로 받는다 — 값 없는 플래그도 켬, `off/false/0/no` 만 끔, 인자 자체가 없으면 ST 기본(지속). 새 불리언 인자를 받을 때 이 함수를 쓴다.

- **카드에 들어 있는 값을 "매크로로만 꺼낼 수 있게" 두지 않는다 (카드 지침 3종 미전송 사고).** — 캐릭터 카드의 `system_prompt` / `post_history_instructions` / `extensions.depth_prompt` 는 임포트 때 저장만 되고 `{{charPrompt}}` 같은 매크로를 프롬프트 세트에 직접 써야만 전송본에 들어갔다. 실리태번은 이 세 칸을 **기본으로** 꾂으므로(Prefer Char. Prompt/Instructions 기본 켬짐), 같은 카드를 같은 프리셋으로 돌려도 스텔라에서만 상태창/캐시트 지시가 통째로 빠져 모델이 그냥 롤플로 흘렀다(게임형 카드에서만 드러나 오래 몰랐다). 페르소나·요약은 이미 "매크로 있으면 그 자리, 없으면 기본 자리" 규칙이었는데 카드 지침만 예외였다. → 카드·페르소나·세션이 가진 내용을 새로 받을 때는 **기본 자리를 먼저 정하고**, 매크로는 그 자리를 옮기는 수단으로만 둔다. 곑가지 둘: 깊이 프롬프트는 ST 에서 `{prompt, depth, role}` **객체**라 그대로 매크로에 넣으면 `[object Object]` 가 전송된다(문자열 카드도 있으니 둘 다 받는다). 그리고 내용이 **대체되는 항목**에 쓴 매크로는 자리 지정으로 세면 안 된다 — 대체로 매크로가 사라지고 자동 삽입까지 막혀 내용이 통째로 증발한다(`macroPlacementTexts(..., replaced)`).

- **전송본 단일 진실 소스를 깨지 않는다 (대전제).** — "API 에 보낼 그 내용"은 오직 `build-session-context.ts` `planSessionRequest()` 한 곳. 실제 생성과 미리보기는 같은 payload 를 쓰고, 미리보기는 전송본과 **byte 단위로 같아야** 한다. 미리보기/생성 전 열린 세션창의 미저장 편집을 먼저 flush(`plugin.flushSessionEdits`). 전송 직전 가공을 새로 추가하면 미리보기 경로에도 동일하게 반영 — 한쪽에만 넣지 않는다.

- **확장을 만들다가 전송본 조립의 공통 기본값·세는 방식을 바꾸지 않는다 (이중 생성 작업 중 생성 전체가 달라진 사고).** — 이중 생성 작업 도중 Core 의 NAI 토큰 계산이 근사→실측으로 바뀌며 "입력 토큰 초과" 거부가 터졌고, 그 뒷수습이 확장과 무관한 공통 경로에 들어갔다: ① `Max Context` 미지정 시 예산을 16000 → **모델 한도 전부**로 ② 토큰을 문자열 대신 메시지 모양으로 세기 ③ 완성본을 재측정해 **최대 3회 재조립**(변수 in-place 갱신 때문에 스냅샷 되돌리기까지 딸려옴). 확장을 꺼도 모든 생성이 배포판과 다른 내용을 보내게 됐다. → 확장 작업의 변경은 **그 확장이 꺼지면 전송본이 byte 단위로 이전과 같아야** 한다(롤백 경계). 한도 초과 같은 공통 문제를 만나면 그 자리에서 고치지 말고 **별건으로 분리**한다. 예산은 `resolveTokenBudget` 한 곳: 기준은 사용자의 `Max Context`(없으면 16000), 다만 모델 프로필 한도에서 **출력 길이만큼 뺀 값**을 천장으로 클램프한다(입력으로 창을 가득 채우면 답이 안 나온다). 재측정 루프 같은 사후 보정 기계를 다시 만들지 말 것.

- **끝이 있는 형식을 요구한다 — 분량 문제를 토큰 상한으로 덮지 않는다.** — 이중 생성 1차의 출력이 계속 흘러넘쳤다: 여러 줄 `이름: 생각` → 수백 줄 대본, 한 줄 `이름: 생각 | …` → 한 줄 안에서 인물을 계속 돌며 2000자. 원인은 하나다 — **종결이 없는 임의 패턴**이라 컴플리션이 무한히 이어 붙일 수 있고, "각 인물 한 번씩"은 패턴상 근거가 없다. **JSON 일 때는 이 일이 없었다**: 닫는 기호가 있는 **학습된 형식**이라 모델이 `}`/`]` 로 닫고 끝낸다. → **JSON 의 종결성을 유지하되 구분자를 줄인다: 이름을 키로 쓰는 객체**(`{"이름":"생각", …}`). 항목당 `"":"",` ≈ 5토큰으로 배열-오브젝트(≈11토큰)의 절반 이하이고, **JSON 객체의 키는 유일하므로 인물 중복이 형식으로 막힌다**(지시문으로 부탁할 일이 아니다). **모델 프로필의 출력 상한을 덮어써서 자르는 건 해결이 아니다** — 문장 중간에서 끊길 뿐이고, 프로필 값은 그 프로필 소관이다.

- **텍스트 컴플리션은 지시로 멈추지 않는다 — 멈추는 건 예시가 만든 패턴과 stop 시퀀스뿐이다.** — "Output ONE line" / "then stop" 같은 문장을 아무리 넣어도 컴플리션 모델은 **직전 패턴을 잇는 기계**라 멈추지 않는다. 실제로 멈추게 하는 것은 둘: ①**앵커 접두어까지 포함한 완성 예시**를 두 번 보여 줘서 "이 패턴은 줄 끝에서 끝난다"를 학습시키는 것(`Private thoughts: …한 줄… \n` × 2) ②**stop 시퀀스**. 한 줄 형식이면 전송본이 `Private thoughts: ` 로 줄 중간에서 끝나므로 **첫 개행이 곧 끝** → 텍스트 경로에 `"\n"` 을 stop 으로 건다. **챗에는 걸지 않는다** — 답변이 개행으로 시작하면 첫 글자에서 잘려 빈 응답이 된다(코드펜스 stop 으로 겪은 사고와 같은 형태). 지시문은 챗 모델용 보조일 뿐, 컴플리션의 통제 수단으로 세지 않는다.

- **인물별 결과를 뽑는 프롬프트는 "여러 줄 목록"으로 쓰지 않는다 — 대본이 된다.** — 이중 생성 1차를 `이름: 생각` **줄마다** 형식으로 뽑게 했더니, 모델이 목록 대신 **수백 줄짜리 대화**를 쏟아냈다(`Yuri: —what?— / Hazama: —she saw him— …`, 생성이 토큰 제한까지 감). 줄 형식이 채팅 로그와 생김새가 같아 이름 셋을 쓰고 나면 주고받기가 자연스러운 이어쓰기가 되고, "각 인물 한 번씩"이라는 제약이 어디에도 없었다. 여는 `[` 는 오히려 여러 줄로 펼치라는 신호였다. → **`default-media-prompts.ts` 의 삽화 프롬프트를 본다**(그 프롬프트만 한 번도 안 샜다): ①출력이 **한 줄**(줄 끝이 곧 끝) ②`OUTPUT FORMAT — copy this shape exactly` + 모양 박기 ③규칙마다 GOOD/BAD ④**완성 예시**(`do NOT output this`) ⑤`NOW DO IT` 로 마지막에 제약 재확인 ⑥앵커가 형식의 첫 글자까지 포함. 형용사로 "짧게/한 줄씩"을 설명하는 것보다 이 여섯 개가 훨씬 강하다. 파서도 같은 규칙으로 방어한다(같은 이름 재등장 = 대화 시작 → 절단, `<think>…</think>` 선제거).

- **`{{char}}` 를 "캐릭터 이름"으로 여기고 프롬프트에 쓰지 않는다 — 스텔라에서 그건 시나리오(카드) 이름이다.** — 이중 생성 기본 세트의 견본 줄을 `{{char}}: <생각>` 으로 썼는데, 소설 세션에서 그 매크로는 **작품 제목**으로 풀려 제목을 발화자로 박은 견본이 섰다. ST 프리셋을 눈으로 훑어 베낀 결과다 — **여기는 캐릭터챗 프론트엔드가 아니라 스토리텔링 엔진**이고, 등장인물은 본문과 카드에서 읽어야 한다. → 인물 자리는 `<name>:` 같은 자리표시자로 둔다. 새 프롬프트/기본값을 쓸 때 매크로가 **이 코드베이스에서 무엇으로 풀리는지**(`context-builder.ts` `macroCtx`) 확인하고 쓴다.

- **부속 호출(확장 기능)에 세션의 생성 수치를 물려주지 않는다 — `paramsOverride` 를 아예 안 보낸다.** — 이중 생성 1차가 `planSessionRequest` 의 `paramsOverride` 를 통째로 넘겨 세션의 출력 제한·샘플링을 물려받았다. 그래서 ①본문 분량 설정(maxOutputTokens)에 1차 결과가 잘리고 ②"입력 한도는 세션 슬라이더를 안 따르는데 출력·온도는 따르는" 앞뒤 안 맞는 상태가 됐다. → **번역·요약·로어북 선별·문단 재생성이 이미 하는 대로** `{profileId, prompt|messages, label}` 만 보낸다. 그러면 출력 길이·샘플링·stop 이 전부 **그 모델 프로필**의 설정이 되어 본문 분량 설정과 자동으로 분리된다. `settingsOverride.params` 도 `undefined` 로 넘겨 입력 예산까지 그 프로필 기준으로 통일한다. 새 부속 호출을 만들 때 이 네 서비스 중 아무거나 먼저 열어본다.

- **stop 시퀀스는 경로별로 키가 다르다 — 한 키로 보내면 한쪽이 조용히 무시된다.** — Core 어댑터 실측: **챗**(anthropic/google/openai/vertex)은 `{...프로필 params, ...paramsOverride}` 로 병합한 뒤 **`stopSequences`** 를 읽어 provider 키(`stop_sequences`/`stopSequences`/`stop`)로 매핑한다. **텍스트**(novelai/openai)는 `paramsOverride` 를 **요청 본문에 그대로 펼치므로** OpenAI 형식 네이티브 키 **`stop`** 이어야 한다(NAI 텍스트도 Core 는 `/oa/v1/completions` 로 가고, Core 자신이 프로필 `stopSequences` 를 NAI 본문 `stop` 으로 매핑한다). NAI **네이티브** `/ai/generate` 의 stop 은 토큰 ID 배열이지만 Core 는 그 경로를 쓰지 않는다(우리가 토큰 ID 를 만들 수단도 없다 — Core 에 토크나이저 API 가 없고 `countTokens` 는 계수 근사 ±10%). → `payload.kind === "text" ? "stop" : "stopSequences"`. **수치를 안 물려주는 것과 stop 을 거는 것은 별개 문제다** — 한꺼번에 빼지 않는다.

- **모델을 갈아끼우는 오버라이드는 `naiFormat` 도 함께 재유도한다.** — 이중 생성 1차가 모델만 바꾸고 `naiFormat` 을 안 넘겨, 세션의 챗 기준 값(OFF)이 따라와 **텍스트 컴플리션 모델에 평문으로** 나갔다. → `settingsOverride` 에 `naiFormat: undefined` 를 함께 실어 `resolveNaiFormat(kind, undefined)` 가 그 모델 종류 기본값(텍스트=ON)으로 떨어지게 한다. 프리셋 순환(`presetToGenerationOverride`)이 이미 같은 이유로 그렇게 한다 — 새 오버라이드 경로를 만들 때 그 함수를 먼저 본다.

- **입력 토큰 예산을 모델 한도에 "딱 맞춰" 채우지 않는다 — 완성본을 Core 방식으로 재보고 넘치면 다시 조립한다 ("입력 토큰 초과" 거부 사고).** — 조립 예산을 Core 프로필의 입력 한도와 같게 잡았더니 생성이 계속 거부됐다(`입력 토큰(N)이 프로필 "X"의 최대 입력 토큰(M)을 초과했습니다`). 우리 계산이 Core 보다 **항상 작게** 나오기 때문이다: ① Core 는 입력을 잴 때 **메시지마다 래핑 오버헤드(+4)** 를 더하는데 우리는 내용 문자열만 셌다 → 메시지 수만큼 과소 계산 ② **조립이 끝난 뒤 붙는 것들**(세션 시작 마커·이어쓰기 이음새 보정 지시문·그룹 발화 지시·텍스트 경로의 이름 프리픽스/NAI 역할 토큰)은 예산에 안 잡힌다. 예산이 16000 고정이던 시절엔 여유가 커서 안 드러났다. → ①은 주입 카운터를 **메시지 모양**으로 재게 하고(`ai.countTokens([{role,content}], profileId)`), ②는 미리 알 수 없으므로 **완성본을 Core 의 거부 판정과 같은 모양으로 실측**(`measureInputTokens`)한 뒤 넘친 만큼 예산을 깎아 재조립한다(최대 3회, `assemble(budget)` 클로저). **재조립할 때 `variables` 를 원본 스냅샷에서 다시 시작한다** — `buildContext` 가 in-place 로 갱신하므로 안 그러면 같은 `addvar` 가 두 번 적용된다. 전송 직전 가공을 새로 추가할 때 이 실측 경로가 그대로 살아 있는지 확인할 것.

- **본문이 아닌 부산물 생성에 본문의 출력 제한(maxTokens)을 물려주지 않는다.** — 출력 제한은 "본문을 한 번에 이만큼만 써라"는 **분량 설정**이다. QR `/gen` 이 `planSessionRequest` 의 `paramsOverride` 를 통째로 넘겨, 7~11 섹션짜리 외전이 본문 분량에 맞춰 중간에 잘렸다. → 부산물 경로는 `util/generation-params.ts` `withoutOutputCap(...)` 로 `maxTokens`/`max_tokens` 만 떼고 샘플링은 유지한다(키를 빼면 Core 가 그 프로필 설정값으로 떨어짐). 판단 기준은 **용도**: 본문/선채팅처럼 세션 본문을 이어 쓰는 것은 그대로 쓰고, 번역·삽화·요약·문단 재생성·`/gen` 처럼 본문이 아닌 결과물은 물려받지 않는다.

- **커맨드의 맨 인자가 비어 있으면 "값이 없다"가 아니라 "앞 결과를 쓰라"는 뜻이다 (QR 결과 증발 사고).** — ST 슬래시커맨드는 맨 인자를 **안 적으면** 파이프 값이 그 자리에 온다. 우리 실행기는 그걸 몰라 `/gen … | /sendas name="{{char}}"` 를 "본문 빈 문자열"로 보고 **조용히 통과**시켰다. 결과가 세션에도 화면에도 안 남아 가십지·자동사냥·마법 신문·비밀 일기장·극대본 작성이 전부 "눌러도 아무 일 없음"이 됐다(오류도 없어 원인 추적이 어려운 종류). → `runCommand` 의 `body()` 한 곳이 규칙을 소유한다: **원문이 비어 있으면** `state.pipe`, 적혀 있는데 매크로가 빈 값으로 풀렸으면 그대로 빈 값("안 적음"과 "비어 있음"을 뭉개지 않는다 — `/setvar` 의 값 인자 판정이 여기 의존). 인자가 내용이 아니라 **대상 지정**인 커맨드(`/hide` `/trigger` `/flushvar` `/flushinject` `/getglobalvar`)만 `rawBody()` 로 파이프를 막는다 — 안 그러면 `/gen … | /hide` 가 엉뚱한 메시지를 숨긴다. **새 커맨드를 추가할 때 이 둘 중 어느 쪽인지 먼저 정한다.**

- **`/sendas name=` 의 이름을 해석 못 했다고 버리지 않는다 (남의 발화가 캐릭터 말풍선으로 뜬 사고).** — 그룹 멤버와 이름이 안 맞으면 `speaker` 를 안 붙여 호스트 발화로 떨어졌고, "마법 신문"이 캐릭터 본인의 말풍선으로 보였다. → 멤버가 아니면 **익명 발화자**로 남긴다(`node-meta.json` 의 `speakerName`). 이때 **본문에 `이름:` 접두어를 박지 않는다** — 본문은 문자 오프셋 기준이라 접두어 한 줄이 편집 패치·번역 문단 키·삽화 앵커를 전부 밀어낸다. 이름은 표시 계층(챗 = 이름 라벨+이니셜 아바타, 소설 = 글자 0개 이름표 위젯)에서만 그린다.

- **"AI 에게 안 보낸다"를 본문 밖으로 빼서 구현하지 않는다 (`/comment` 호환 파손).** — ST 는 결과를 **항상 대화 로그에 남기고** 프롬프트에서만 뺀다. 우리는 `/comment` 를 본문 밖 노트로 저장해 "AI 엔 안 감"을 공짜로 얻었지만, QR 을 프롬프트 숏컷으로 쓰는 카드가 기대하는 자리(대화 로그)에 결과가 없어 다음 커맨드가 물리지 않았다. → 결과는 본문 노드로 남기고 **전송본 조립에서만 뺀다**(`node-meta.json` 의 `hidden` → `planSessionRequest` 한 곳: 챗은 nodeId 필터, 소설은 `spansExcludingNodes`). 표시는 클래스만 얹어 흐리게 — **본문 textContent 를 바꾸면 편집 diff/offset 이 깨진다.** 챗 로그의 꼬리 제외(`excludeTailAssistant`)는 **숨김 필터보다 먼저** 한다(갈아끼울 메시지가 숨김이면 이미 없어서, 나중에 pop 하면 멀쩡한 앞 메시지가 잘린다).
- **본문을 AI 에게 넘기는 코드가 각자 `buildSpans` 를 부르면 숨김·삭제가 새 기능마다 다시 샌다.** — "AI에게 숨김"을 `planSessionRequest` 한 곳에서만 걸렀더니 **이어쓰기에서만** 통했다. 요약·로어북 자동 생성·세션 제목·반복 표현·집필 문체 꼬리·스텔라 폰이 저마다 원문을 다시 읽어, 눈감긴 QR 결과가 그 경로로 AI 에게 갔다(요약에 숨긴 내용이 남는다는 제보). 같은 자리에 두 번째 사고가 겹쳐 있었다 — 요약·로어북은 `buildSpans(session, 경계노드)` 로 **그 시점 본문**을 되감아 재료를 만들어서, 나중에 지운 대목이 요약을 전부 지우고 다시 만들어도 계속 되살아났다. → 창구는 `util/ai-body-text.ts` 하나(`sendableText`/`sendablePassage`/`hiddenNodesOf`)이고, 확장은 `ExtensionContextInput` 의 `bodyText`/`hiddenNodeIds` 를 받아 쓰며 본문을 재구성하지 않는다. 구간 재료는 `textBetweenNodes` 로 **지금 본문**에서 자른다(`genNodeId` 귀속이라 나중 편집이 제자리에 반영된다). 하네스가 `src/services/**`·`src/extensions/**` 의 직접 호출을 막고, 표시·오프셋 예외만 `// body-raw: 이유` 로 남긴다. **"확장마다 따로 고치기"로 되돌아가지 말 것** — 그러면 확장을 하나 추가할 때마다 같은 제보가 다시 온다.

- **프리셋 랜덤 순환은 전송 1회용 오버라이드만.** — 과거 applyPreset silent 적용이 활성 설정·우측 UI 까지 바꾸는 회귀가 반복됐다. → 생성 직전 `pickRotationPreset()` → `presetToGenerationOverride`(모델/파라미터/프롬프트 세트/이어쓰기 보정만, 미디어 제외) → `planSessionRequest` 의 `settingsOverride` 로만 얹는다. 활성 설정(세션 meta/PluginData.current)과 UI 는 절대 불변. 사용자가 직접 프리셋/모델을 고르면(`notePresetRotationManualChoice`) 다음 1회는 순환 스킵.

- **기본 프롬프트 세트에 `chatSummary` 마커를 넣지 않는다.** — ST 에 없는 Stella 전용 항목이라 요약 기능에 귀속. 요약 주입은 `planSessionRequest` 게이트(켜져 있을 때만, 명시적 마커/`{{summary}}` 있으면 그 위치 존중·자동 삽입 안 함 — 페르소나와 같은 규칙).

- **Stella 전용 prompt marker 를 만들지 않는다. 특히 `personaDescription` marker 금지.** — 페르소나는 `{{persona}}` 매크로(명시 위치) 또는 기본 위치(캐릭터 설명 앞) 자동 삽입.

- **폰 공유 다이제스트(v2 §8.1)를 세션 전송본 경로에 넣지 않는다.** — `PhoneService.buildSharedDigest` 는 폰 **내부 생성**(문자/SNS/방송 답장)에만 붙는다. 세션 `phone` 컨텍스트 슬롯(planSessionRequest 경유, phone-extension `contributeContext`)에는 절대 넣지 않는다 — 다이제스트는 시간순 정렬·in-memory 방송 상태를 쓰므로 미리보기·생성 byte 동일 대전제를 깬다. 세션 주입에 들어가는 SNS "봤는지"(§8.2 `sawSnsPost`)는 반드시 **결정적**(scenarioId 기준 `hashRatio`, Math.random 금지)이라 byte 동일이 유지된다. 두 경로를 헷갈려 다이제스트를 슬롯에 흘리지 말 것.

- **"문단" 정의는 앱 공통 `tokenizeParagraphs`(연속 줄바꿈 `\n+` = 구분자 하나, 그 사이 내용 블록 = 문단) 하나만 쓴다.** — 작가노트를 "끝에서 4번째 문단" 앞에 넣는 `context-builder.ts` `storyToMessages` 가 예전엔 빈 줄(`\n\s*\n`) 기준 자체 splitParagraphs 로 문단을 셌다. 소설 본문은 줄바꿈 하나로 문단을 나누므로 본문 전체가 한 문단으로 뭉쳐 작가노트가 맨 위에 붙는 버그(2026-07-21 수정). 엔터를 한 번 띄우든 두 번 띄우든(사용자·모델마다 다름) **내용 있는 블록만** 문단으로 세야 한다(공백만 있는 블록 제외). 번역/문단재생성이 쓰는 `translate-paragraphs.ts` `tokenizeParagraphs` 를 재사용하고, 원문 줄바꿈은 토큰째 보존해 before+after 가 본문과 byte 동일하게 자른다.

- **이어쓰기 이음새 보정에서 장면 구분선(`***`)을 미완성 문장으로 취급하지 않는다.** — `anchorEndsParagraph`(`continuation-anchor.ts`)가 앵커 끝 글자만 보고 문장부호가 아니면 "문장 중간"으로 판정했다. 본문이 `***`로 끝나면 앵커가 `…문장.\n\n***`가 되는데, 끝 글자 `*`가 종결부호가 아니라 `collapseSeam=true`가 되어 (1)이어쓴 응답 앞머리 줄바꿈을 다 지우고 (2)본문 꼬리 공백 delete 패치까지 걸었다 → `***`가 다음 문단과 뭉개지고 빈 줄이 사라짐(2026-07-23 수정). `***`는 오히려 문단이 확실히 끝나는 자리다. → 앵커의 마지막 줄이 장면 구분선(`/^\*{3,}$/`, 공백 무시)이면 `anchorEndsParagraph`가 true 를 돌려 이음새 줄바꿈을 보존한다. 이 가공은 저장·전송 단계라 AI 출력 정규식으로는 못 되돌린다. 구분선 정의는 `util/pro-convert.ts` `isSceneBreakParagraph` 와 같게 유지. **같은 사고의 짝: 본문이 `***`로 끝나면 앵커 자체를 만들지 않는다**(`extractAnchorSentence` → null, 2026-08-02 수정) — 앵커 지시문은 "이 문장을 그대로 받아쓰고 이어서 계속 써라 / 진행 중인 문단이니 새 문단의 시작으로 취급하지 마라"라서, 구분선 앞 문장이 앵커가 되면 모델이 장면 전환을 무시하고 앞 장면을 계속 썼다(사용자 지적: "절대로 다음 장면을 안 쓴다"). 장면 구분선 뒤는 이을 이음새가 없는 자리다.

- **이어쓰기 중복 제거를 앵커 하나에만 걸지 않는다 — 모델은 앵커보다 앞에서부터 본문을 되받아쓴다.** — 앱커 매칭(`findAnchorEnd`/`fuzzyPrefixSkip`/`fallbackSkip`)은 응답 맨 앞에서 **앵커 그 문장**을 찾는다. 본문이 문장 중간에서 끊겨 앵커가 한 단어 조각(예: `There`)이면 모델은 그 조각만 받아쓰지 않고 **그 조각이 속한 대사·문단을 통째로 다시 쓴 뒤** 이어가서, 세 단계 매칭이 전부 실패하고 문단이 통째로 중복됐다(사용자 지적: "이젠 아예 앞 문장 덮어쓰지도 않는데?", 2026-08-19 수정). → 앵커가 아니라 **본문 꼬리 자체**와 응답 앞머리를 맞춰 보는 `tailOverlapSkip(parentText, raw)` 를 `anchorSkipFinal`/`anchorSkipStreaming` 에 추가했다(둘 다 `parentText` 선택 인자). 가장 긴 겹침을 고르고, 서식·문장부호는 양쪽에서 건너뛰며 실질 글자만 정규화 비교(퍼지 매칭과 같은 규칙), 우연 일치 방지로 최소 12자(`OVERLAP_MIN_HARD`) 이상일 때만 자른다. 스트리밍 중에는 되받아쓰기가 진행 중이면(`tailOverlapPending`) 표시를 보류해 중복이 화면에 비치지 않게 한다. 앵커 추출 규칙(`ANCHOR_MIN_CHARS`)을 건드려 해결하려 하지 말 것 — 생성 결과는 지시대로 안 온다는 게 전제다.

- **이어쓰기 이음새를 정리할 때 걷어내는 것은 줄바꿈이지 띄어쓰기가 아니다.** — `finalizeAnchorStrip`(`session-view.ts`)이 문장 중간 이음새(`collapseSeam=true`)에서 이어쓴 응답의 선행 공백을 `replace(/^\s+/, "")`로 통째로 지우고 본문 꼬리 공백까지 delete 패치로 걷어냈다 → 한국어·영어처럼 띄어쓰기를 쓰는 글에서 "천천히문을"처럼 앞뒤 단어가 들러붙었다(사용자 지적: "이걸 방지하려고 이음새 보정을 쓰는 건데", 2026-08-18 수정). 줄바꿈만 문제이고 공백 한 칸은 문장을 잇는 데 필요하다. → `continuation-anchor.ts` `seamSeparator(before, after)`(순수 함수)로 판정: 이음새에 공백이 하나라도 있었고 양쪽 인접 글자 중 하나라도 띄어쓰기를 쓰는 문자(라틴/키릴/한글/숫자)면 공백 한 칸을 남기고, 일본어·중국어(단어 사이 공백 없음)나 단어 중간에서 끊긴 이음새(양쪽 다 공백 없음)면 그대로 붙인다. 이 가공은 저장 단계라 나중에 되돌릴 수 없으니, 이음새 공백 규칙을 손댈 땐 두 언어군을 함께 확인한다.

- **이어쓰기 중복 제거(앵커 반복 절단)는 모델이 앵커를 글자 그대로 재현할 거라 가정하지 않는다.** — 중복 제거는 "모델이 다시 옮겨 쓴 앞부분을 잘라내는" 방식인데, `findAnchorEnd`(엄격 매칭)는 앵커를 **바이트 그대로** 재현해야만 잘랐다. 모델이 앵커 끝 `***`를 빼먹거나(장면 전환 없이 같은 장면 이어씀), 여는 따옴표(「")를 누락하거나, 곧은/둥근 따옴표·말줄임표(…↔...)·전각/반각을 바꿔 재현하면 매칭 실패 → **앞문장이 안 잘리고 그대로 중복**됐다(2026-07-23 수정). → `anchorSkipFinal`/`anchorSkipStreaming` 에 정규화 퍼지 접두 매칭(`fuzzyPrefixSkip`/`matchAnchorFuzzy`)을 엄격 매칭 실패 뒤 단계로 추가: 서식·문장부호(`isSoft`=LEAD_SKIPPABLE+TERMINATORS)는 양쪽에서 자유롭게 건너뛰고, 실질 글자만 전각→반각 정규화(`normHard`)해 비교. **앵커 실질 전체가 재현됐을 때만**(최소 `FUZZY_MIN_HARD`=3자) 자르고, 실질 글자가 도중에 어긋나면 안 자른다(정상 이어쓰기 오삭제 방지). 앵커가 소프트로 끝났을 때만 재현된 꼬리 문장부호를 걷어내되 **공백은 분리자로 남긴다**(앵커가 실질 글자로 끝나면 뒤 `」`는 이어쓰기이므로 안 건드림). 매칭을 더 헐겁게 할 땐 반드시 "정상 이어쓰기를 중복으로 오인해 지우는" 반대 사고를 함께 막는다.

- **자동 생성물이 자기 출력을 다시 재료로 먹는 루프를 만들지 않는다.** — SNS 갱신이 매번 "같은 세션 장면 + 직전 피드"를 재료로 "새 글 최소 N개"를 요구하니, 세션에 진행이 없으면 모델이 사건을 발명하고 다음 배치가 그 발명을 또 확장했다. 결과적으로 **SNS 가 세션보다 스토리를 앞질러 갔다**(2026-07-26 수정). → 소비 지점을 기록하는 **북마크**(`PluginData.snsProgress`)를 두고 "북마크 이후 새 진행분"만 사건 재료로 쓴다. 이전 구간은 지우지 말고 **배경(BACKGROUND ONLY)** 으로 따로 붙여 모순 방지 용도로만 남긴다 — 컨텍스트를 빼면 캐릭터가 자기 상황과 어긋나는 글을 쓴다. 진행분이 없으면 **잡담 모드**(새 플롯 사건 발명 금지)로 강등하되 생성 자체를 멈추지는 않는다. 북마크 전진은 반드시 **저장 성공 후**.

- **자동 생성 피드를 "세션 사건 반응"으로만 정의하지 않는다.** — 사건 반응만 시키면 NPC 들이 남의 세션을 전지한 관전자처럼 논평하는 "아침 드라마 시청자" 글이 나온다(사용자 지적). 세션 첨부의 목적은 **모순 방지와 개연성**이지 관전평 생산이 아니다. → 기본은 **화면 밖 일상**(플레이하지 않는 시간의 삶)이 다수(`snsDailyRatio` 기본 70%)이고 사건은 소수. 경계는 "**본편 줄거리를 진전·해결·확대하면 금지, 그 인물의 사생활·일상은 자유**" — 일상까지 막으면 리얼함이 죽는다.

- **상한을 두면 초과분에 "익명 폴백"을 두지 않는다.** — SNS 신규 계정 상한(배치당 3명)을 넘긴 작성자를 "등록 없는 익명 작성자"로 통과시켰더니 상한이 아무 의미가 없어 엑스트라가 무제한으로 판쳤다(2026-07-26 수정). 상한을 넘긴 활동은 **폐기**한다. 같은 사고의 짝: 명부(캐스트)를 프롬프트에 **명시하지 않으면** 모델은 이름을 스스로 찾아야 하고, 못 찾으면 발명한다 — "재사용하라"는 지시만으로는 재등장률이 오르지 않는다. 비율 규칙도 지시만으로는 안 지켜지므로 파서/엔진이 잘라내는 강제(`extraQuota`)를 함께 둔다.

- **"서사가 진행됐다"를 AI 생성으로만 판정하지 않는다.** — 폰 키워드 트리거와 방송 자동 감지가 `onGenerationComplete`(AI 생성) 훅에만 붙어 있어서, 사용자가 직접 "방송을 켰다"라고 쓴 전개를 통째로 놓쳤다(2026-07-26 수정). 챗 전송·소설 유저 입력도 서사 진행이다. → 확장 API 에 `onUserText` 훅을 추가하고 두 세션 뷰의 **확정된 사용자 입력 지점**에서 발화한다(챗 = 전송 1회, 소설 = 타이핑 커밋을 모아 **이어쓰기 직전 1회** — 커밋마다 부르면 AI 호출이 낭비된다). 새 자동 판정 기능을 붙일 때 두 훅 모두에 붙였는지 확인한다.

- **분기 상태를 갖는 부가 기능(방송 등)은 활성 경로에서 그 시작점이 사라진 경우를 처리한다.** — 스텔라튜브 방송은 `startedNodeId` 이후 노드에 반응을 매다는데, 되감기·분기 전환으로 시작점이 활성 경로에서 빠져도 LIVE 표시가 그대로여서 "방송 켜기 전 지점인데 생중계 중"인 모순이 났다(2026-07-26 수정). → 표시(`tubeOnActivePath`)와 생성(`generateTubeReaction` 초입 가드) 양쪽에서 경로 포함 여부를 확인하고, **파일의 live 는 끄지 않는다**(끄면 앞으로 되돌아갔을 때 사용자가 다시 켜야 한다 — 되돌릴 수 있는 상태를 파괴하지 않는다).

- **키워드 매칭만으로 서사에 개입하는 기능(방송 자동 시작 등)을 켜지 않는다.** — 폰 방송 자동 감지 초판이 생성문에 "방송/스트리밍/配信" 글자가 **포함되기만 하면** 즉시 방송을 시작하고 스트리머를 무조건 로그인 페르소나로 잡았다. "어제 방송 봤어?" 같은 언급, 남의 방송 시청, 과거 회상에도 켜졌고 서사 속 실제 방송자를 무시했다(2026-07-26 수정). → 키워드는 **판정 요청 신호**로만 쓰고, 실제 개입 여부는 모델이 장면을 읽고 판정한다(`tryAutoStartStream` + `phoneStreamDetect` 프롬프트). 판정 결과의 인물은 **장면 인물 명부**(`collectSceneCast`: 호스트 시나리오 + 그룹 멤버 + 장면에 이름이 실제 등장하는 계정, 로그인 페르소나 제외)로 거르고, 매칭 실패면 **아무 것도 하지 않는다** — 자동 경로에 "일단 페르소나로" 같은 폴백을 두지 않는다(오작동이 사용자 스토리를 납치한다). 판정 호출에는 busy 가드 + 분 단위 스로틀을 함께 건다.

- **취소(`cancelled`)를 "사용자가 누른 것"으로 단정해 조용히 넘기지 않는다.** — Core 는 자기 **요청 시간 초과**도 취소와 똑같은 `code:"cancelled"` 로 돌려준다(`generation-service.ts` 의 `setTimeout(() => ctrl.abort())` → `normalizeError`). 그래서 "취소면 토스트 생략"이 곳곳에 있었고, 그 결과 집필 변환(`performProConvert`)·챗 양방향 변환·자동 번역이 시간 초과로 죽으면 **이어쓰기/전송이 통째로 멈추는데 화면에도 AI 로그에도 아무 흔적이 없었다**(2026-07-31 수정). 판별 기준은 간단하다: **우리가 그 호출에 `signal` 을 넘겼는가.** 안 넘긴 경로(번역·집필 변환·로어북 선별·요약 등)의 `cancelled` 는 사용자 취소일 수 없으므로 반드시 알린다. 사용자가 켜 둔 자동 실행(자동 번역/삽화)의 실패도 `console.warn` 으로만 남기지 않는다 — 콘솔은 사용자가 보지 않는다.

- **생성 재진입 잠금은 "전송본이 확정된 뒤"가 아니라 "준비 시작"에 건다.** — `this.generation` 은 payload 가 확정된 다음에야 세팅되는데, 그 앞의 준비 단계(집필 변환·자동 실행 QR·로어북 AI 선별·컨텍스트 조립)만도 AI 호출을 여러 번 하며 수십 초가 걸린다. 그동안 이어쓰기 버튼은 멀쩡한 재생 아이콘이라 한 번 더 눌리고, 두 번째 흐름이 같은 뷰에서 나란히 돌며 `this.generation` 을 덮어써 서로의 스트림을 끊었다(2026-07-31 수정). → `preparing` 플래그를 준비 시작에 세우고 `generation` 을 세팅하는 순간 넘겨준다(자동 번역/삽화가 도는 뒷정리 구간까지 버튼을 묶지 않기 위함). 생성 경로에 **AI 호출을 하는 준비 단계를 새로 추가할 때는 잠금 구간 안인지 확인**한다.

- **버튼 핸들러의 `() => void this.handleX()` 는 실패를 삼킨다.** — 요청을 보내기 전 단계에서 예외가 나면 사용자에게는 "눌렀는데 아무 일도 없고 로그에도 요청이 없는" 상태로만 보인다(원인 추적 불가). 생성 경로의 진입점(`handleContinue`/`handleRegen`)은 `views/report-failure.ts` `reportSessionFailure` 로 실패를 반드시 화면에 남긴다. 새 생성 진입점을 만들면 같은 처리를 붙인다.

- **AI 보조 기능의 프롬프트·동작 수치를 하드코딩하지 않는다.** — 로어북 AI 선별 초판이 지시문과 본문 첨부량(4000자)을 코드에 박았다가 교정됨(2026-07-17). 사용자는 "내가 모르는 데서 어떻게 돌아가는지 모르게 돼 있는 것"을 명시적으로 거부한다. 새 AI 기능의 지시문은 편집 가능한 미디어 프롬프트(`default-media-prompts.ts` 버킷 + `renderMediaPromptPicker`)로, 첨부량/주기 같은 수치는 설정 UI 로 노출한다. 숨은 추가 지시문(엔진이 프롬프트 앞뒤에 몰래 붙이는 텍스트)도 두지 않는다 — 편집 화면에 보이는 전문이 그대로 전송돼야 한다. 기본 프롬프트는 텍스트컴플리션 모델 기준으로 짠다(다른 기본 프롬프트처럼 끝에 "Selection:" 류 응답 오프너, 재료는 `{{main}}`/`{{lorebook}}` 위치 매크로).

- **챗 첨부 원본 이미지를 매 후속 턴마다 다시 보내지 않는다.** — 이미지 base64를 대화 이력 전부에 계속 싣으면 입력 크기와 이미지 토큰 비용이 턴마다 누적된다. 첨부 시 비전 캡션을 한 번 저장하고 모든 이후 전송본에는 그 캡션을 넣되, `supports.vision`인 챗 프로필에는 **바로 답할 마지막 사용자 첨부 턴**의 원본만 멀티모달 블록으로 보낸다. 재생성은 assistant 꼬리를 제외하면 같은 사용자 턴이 마지막이므로 원본을 다시 볼 수 있다. 이 결합도 `planSessionRequest()` 안에서만 하며 미리보기는 원본 이미지 장수를 함께 표시한다.
