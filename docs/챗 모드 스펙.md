# 챗 모드 스펙 (M6)

> 챗 모드의 **확정 설계와 가드레일**. 챗 관련 변경 전 필독.
> 대원칙: **챗 모드는 소설 모드를 건드리지 않는다.** 소설 쪽 코드 변경은 배관 공통화에 한정하며 소설 동작은 변하지 않는다.
> 현재 동작·진입점은 `구현현황.md`("챗 모드"), 사고 교훈은 `회귀금지.md`.

---

## 확정 결정

| 항목 | 값 |
|---|---|
| 세션 뷰 | **완전 별도 뷰** (`VIEW_TYPE_CHAT_SESSION = "ggai-stella-chat-session"`, `chat-session-view.ts`). 소설 세션뷰와 코드 공유 안 함 |
| 데이터 | 소설과 **같은 session.json 스키마**(같은 SESSIONS 폴더, 같은 store). `meta.mode: "chat"` 로만 구분 |
| 메시지 모델 | **노드 1개 = 메시지 1개**(append 패치 1개). span author 는 챗에서 무의미 — 역할은 노드 kind 로 결정 |
| 역할 매핑 | `root`/`ai-continue`/`ai-regen` → assistant, `user-write` → user, `user-edit` → 편집(대상 역할 유지) |
| 분기 | 챗(메시지) 단위. 스와이프 = 형제 이동(getSiblings), 재생성 = ai-regen 형제 — 소설과 같은 트리 기계 |
| 첫 메시지 | first_mes = 루트 AI 메시지, alternate greetings = 형제 루트 = 첫 메시지 스와이프. **챗은 대형 씨드 분할 안 함**(통짜 1노드). ST 임포트에서 유저가 먼저 시작한 채팅은 첫 메시지가 `user-write`(parent=null) |
| 메시지 편집 | 소설처럼 **새 노드(user-edit, replace)로 파생** — 제자리 수정 금지(요약 확장 공통 접두사 가정 보호, 이력 보존) |
| UI | 말풍선 목록 + **하단 채팅 입력창** + 소설과 같은 모양의 하단 툴바(리모컨). 전송 = 유저 메시지 + 자동 AI 응답 |
| 삽화 | AI 말풍선 밑 캐러셀(노드 기준 illustrations.json). 인라인 앵커 계산 안 씀, `출력 위치` 설정은 챗에서 비노출 |
| 번역 | translations.json(문단+해시) 그대로, 표시는 말풍선 단위로 챗 뷰가 소유 |
| 모드 판정 | `meta.mode === "chat"` 명시된 세션만 챗. **누락/불명 = 무조건 소설**(기존 세션 오배정 차단) |

## 만들지 않는 것

- 소설↔챗 세션 상호 변환(모드는 생성 시 고정)
- 챗 전용 프롬프트 세트 — 기본 세트 2종이 chat 모드에서 그대로 동작(chatHistory 마커가 메시지 목록으로 치환)
- 소설 전용 기능의 챗 이식: 이어쓰기 이음새 보정(continueAnchor), 번역 split 2분할, 삽화 인라인 앵커
- (그룹/멀티캐릭터 채팅은 G2 트랙 — `선채팅-그룹챗 남은작업.md`)

## 공유 지점과 충돌 대응

1. **세션 열기/추적 배관** — "세션 호스트 뷰" 공통 창구(`src/views/session-host.ts` `isSessionHostView`/`getSessionHostLeaves`)로 파일 조회/미저장 커밋/노드 스크롤을 통일하고, `openStellaSession` 이 mode 로 뷰 타입 라우팅(`resolveSessionViewType`, mode==="chat" 명시 시에만 챗 뷰). 페르소나 기억, 미리보기 flush, 디테일 추적, rename retarget, 갤러리 점프, 패널 셸 판정이 전부 이 창구를 탄다.
2. **뷰 혼입 방지** — 열기 진입점 라우팅 + 각 뷰의 방어(자기 모드 아닌 세션을 받으면 맞는 뷰로 넘김).
3. **전송본 조립(planSessionRequest 공유)** — 챗 게이트: continueAnchor 는 mode!=="chat" 에서만. 챗 세션 로그는 span author 추측이 아니라 **노드에서 직접**(`buildChatLog`, 연속 같은 역할 병합 금지). 미리보기=전송본 대전제 유지.
4. **활성 설정/프리셋 공유** — 모델/파라미터/프롬프트 세트/프리셋은 두 모드 공용. 소설 전용 항목(이음새 보정/NAI 형식 체크/문단 재생성)은 챗 세션 활성 시 디테일 뷰에서 숨김(`ggai-detail-chat-session` 루트 클래스).
5. **생성 후처리** — 요약/번역/삽화 자동 실행 + 확장 훅(`runGenerationComplete`)은 공용 함수로 두 뷰가 호출(복붙 금지).
6. **IME/모바일** — 챗 뷰도 EditGuard/전역 IME 게이트(`runWhenImeIdle`) 필수. 스트리밍 말풍선 갱신이 조합 중 DOM/Selection 을 건드리지 않게. 하단 입력창 safe-area 는 env() 만.

## 챗 데이터 규칙

`src/util/chat-messages.ts`: `buildChatMessages`(경로 워크 + replace/delete 를 메시지 경계 유지하며 반영, 빈 메시지 = 삭제) / `buildChatLog`(trim, 연속 같은 역할 병합 금지) / `chatRoleOfKind` / `CHAT_MESSAGE_SEPARATOR`("\n\n" — 두 번째 메시지부터 append 앞에 붙임, **평탄화 본문 = 메시지 텍스트 연결과 바이트 동일** 불변식).

**말풍선 표시**: `applyMacros`(표시 전용 ctx) → 표시 정규식 → `message-format.ts` `formatMessageHtml`(**마크다운 전반** — 표·목록·인용·제목·코드블록·링크·강조, marked + GFM + breaks) → `safe-html.ts` `renderSafeHtml`(화이트리스트 살균, `styleScope: ".ggai-chat-bubble"`) → `code-copy.ts` `attachCodeCopyButtons`. 표시본에는 `.ggai-md` 클래스가 붙는다(수정칸·스트리밍은 안 붙어 `pre-wrap` 유지, 폰 뷰가 쓰는 예전 포매터 `chat-format.ts` 도 영향 없음). **빈 줄은 접지 않는다** — 마크다운은 빈 줄을 접으므로 빈 줄 2개 이상인 자리에 `<ggai-sep n>` 표식을 심고 살균 단계가 `.ggai-chat-para-sep` 여백 블록으로 바꾼다(빈 줄 1개 = 보통 문단 경계는 `<p>` margin 이 담당).

**말풍선 수정 = 수정 버튼**(클릭 편집 폐지): 이름줄 끝 연필 버튼으로만 편집칸이 열리고(`startBubbleEdit` → 재렌더 → `openBubbleEditor`), 열린 말풍선 하나만 `contenteditable` 이 된다. 나머지는 읽기 상태라 링크·접기·이미지·선택지 버튼이 살아 있다. 닫기 = 완료 버튼(`flushPendingEdits`) / Esc(`cancelBubbleEdit`, 커밋 안 함). blur 는 **닫지 않고 커밋만** 한다(ST `.mes_edit` 과 같은 수명). 편집 중 표시는 raw — 커밋은 항상 raw 기준이라 diff/offset 불변. 재렌더 가드 `isBubbleEditing()` = **수정칸이 열려 있고**(editing != null) 포커스가 그 안 + IME 조합 — 닫힌 뒤에는 포커스가 남아 있어도 재렌더를 막지 않는다. 번역 보기에서는 수정 버튼이 번역문 편집을 열고, 옆 전환 버튼으로 같은 자리에서 원문 편집으로 갈아탄다(`editing.target`). 챗 뷰는 모바일 탭 게이트(`tap-to-edit`)를 쓰지 않는다 — 편집이 버튼으로만 열리므로 게이트가 지킬 것이 없다(소설 뷰는 그대로 쓴다).

**대사 표시**: `"…"` `“…”` `「…」` 등을 `<q>` 로 감싸 색을 준다(ST `messageFormatting` 과 같은 교체 순서·범위 — 코드블록·인라인 코드·`<style>` 안은 건드리지 않고, 태그 속성의 따옴표는 자리표로 치운 뒤 되돌린다 — `class="hud"` 가 대사로 잡히면 마크업이 깨진다). 본문에 따옴표 글자가 그대로 남으므로 CSS 에서 `quotes: none` 으로 브라우저 인용부호를 끕다.

**재생성 = "마지막 AI 메시지 갈아끼우기"**(`regenerateLastAssistant`, flush 먼저): 리프가 그 메시지면 형제 분기, 리프 뒤에 편집 노드가 붙어 있으면 편집 보존(새 ai-regen = delete+append, `planSessionRequest({excludeTailAssistant})` 로 컨텍스트 제외). "수정 후 재생성하면 수정 증발" 회귀 금지(하네스 고정).

**번역 보기 직접 편집**: 번역 말풍선도 직접 편집 — focus 시 문단 스팬+원자 구분자 구조로 스왑 → 바뀐 문단만 `translations.json` 에만 저장(본문 불변), blur 시 복귀. 커밋 방어는 소설 번역 뷰와 동일.

## 텍스트 컴플리션 모델 지원 (ST 호환)

챗 세션을 텍스트(NovelAI) 프로필로 생성할 때 (ST `formatMessageHistoryItem`/`modifyLastPromptLine`/`getStoppingStrings`/`cleanUpMessage` 참조):

- **전송본** (`planSessionRequest`, 미리보기=전송본 유지): mode==="chat" + text 프로필이면 `text-completion-prompt.ts` `applyChatTurnNames` 가 히스토리만 `이름: 내용` 턴으로 프리픽스(유저=페르소나 이름, AI=시나리오 이름)하고 끝에 `{{char}}:` 오프너를 붙인 뒤 평문/NAI 평탄화. 히스토리 사이 주입/메모리/작가노트는 불변.
- **스탑 = 클라이언트 절단**: NAI text API 는 문자열 스탑을 못 넘겨서 text 경로는 비스트리밍 후 `trimChatCompletionOutput` 후처리 — (1) 끝의 반쯤 잘린 `\n{{user}}:` 제거 (2) 응답 전체가 유저 턴이면 폐기(빈 응답 무산) (3) 첫 `\n{{user}}:` 부터 절단 (4) 줄 앞 `{{char}}:` 라벨 제거 (5) 유저 턴 못 만나고 끝났으면(어시스턴트 턴 잘림) 미완성 마지막 문단 제거(종결부호로 안 끝나는 마지막 문단만, 앞에 다른 문단 남아 있을 때만). 유저 턴 만났으면 문단 제거 안 함. 챗 뷰 runGeneration text 분기에서만 — 소설 전송본/후처리 불변.

## UI 세부 (회귀 금지)

- **리모컨 = 입력창 아래, 소설 하단 툴바와 같은 모양**(`.ggai-session-toolbar` 공유): 가운데 이어쓰기 CTA 자리만 입력창이 대신하고 나머지 동일 — undo/redo/끝으로, 번역(탭=입력창 우선/꾹=자동)·삽화·문단재생성, 재생성·◀ n/m ▶, 세이브·보기 스타일·우측 패널. redoStack 은 새 커밋(전송/편집/생성/문단재생성 적용)마다 초기화.
- **상단 뷰어 바** — 소설과 같은 자리·모양(모바일=뷰 헤더 액션/PC=플로팅 줄): [로비(log-out)][갤러리][원문↔번역]. `goToLobby()` = flush 후 같은 탭을 대시보드로 전환(stellaPanel 보존).
- **문단 재생성 = 탭 선택 모드**: wand 토글 → 말풍선 탭 = 클릭 지점 문단 앵커(`paragraphIndexFromBubbleClick`, 전역 인덱스 = 앞 메시지 문단 수 합산), **입력창 탭 = 입력창 텍스트 대상**(적용=입력창 교체). 문단 매핑은 글자 오프셋이 아니라 `<p>` 블록 순번 + 블록 안 `<br>` 줄 순번(`lineIndexInBlock`).
- **아바타/이름 라벨** — AI=시나리오 표지·이름, 유저=세션 페르소나 썸네일·이름(우측 정렬).
- **재렌더 스크롤 보존** — `renderMessages` 는 followTail 일 때만 맨 아래로, 아니면 이전 scrollTop 복원(자동 번역/삽화 완료가 화면을 끌어내리는 회귀 방지). 꼬리 바꾸는 동작(전송/생성/undo/redo/끝으로/스와이프)만 followTail 켜고 렌더.
- **모바일 Enter = 줄바꿈**(Shift 부재), PC Enter=전송·Shift+Enter=줄바꿈. 빈 입력 전송 = "AI가 이어서 말함"(의도된 기능).
- **챗 읽기 내보내기 = 대화록**: 메시지 단위 굵은 이름 라벨(AI=시나리오, 유저=페르소나), 번역 모드는 슬롯 치환, 삽화는 메시지 뒤 임베드. 소설 내보내기 불변.

## 챗 다음화 = 메시지 단위 인계

챗 tail 을 소설식 문단 뭉치로 심으면 유저 발화까지 AI 덩어리로 뭉개진다. 챗은 `planChatEpisodeTail`(최근 N **메시지** + 직전 요약 경계) → `buildChatEpisodeTailNodes`(메시지 1개=노드 1개, 역할 유지). `startNextEpisode` 가 mode 로 분기, `NextEpisodeModal` 미리보기·라벨("최근 메시지")도 같은 계산 공유.
