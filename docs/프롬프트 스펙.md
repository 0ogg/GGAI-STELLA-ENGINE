# 프롬프트(지침) 데이터 스키마 — Stella 통합

> 원본 SillyTavern Chat Completion Preset (이하 ST 프리셋) 을 기준으로 통합한다.
> NovelAI 등 다른 포맷의 프롬프트가 추후 추가되면 이 스키마로 정규화한다.
> `지침 스펙.md` 는 ST 원문(인용용), 이 문서는 Stella 의 결정 기록이다.

---

## 1. 원본 ST 프리셋 핵심 시그니처

`내취향.json` 같은 ST 프리셋 파일의 식별 키:

```jsonc
{
  "chat_completion_source": "vertexai" | "openai" | "claude" | ...,
  "prompts": [ /* 프롬프트 객체 배열 */ ],
  "prompt_order": [ { "character_id": 100000, "order": [ ... ] }, ... ],

  // 모델 (프로바이더별로 별도 키로 분산되어 있음)
  "openai_model": "gpt-4-turbo",
  "claude_model": "claude-3-5-sonnet-20240620",
  "vertexai_model": "gemini-3-pro-preview",
  // ... 수십 개

  // 샘플러
  "temperature": 1, "top_p": 1, "top_k": 0, "min_p": 0, "top_a": 0,
  "frequency_penalty": 0, "presence_penalty": 0, "repetition_penalty": 1,

  // 컨텍스트 한도
  "openai_max_context": 50000,
  "openai_max_tokens": 30000,

  // 유틸리티 프롬프트 (특정 시점 자동 삽입)
  "impersonation_prompt": "...",
  "new_chat_prompt": "...",
  "new_group_chat_prompt": "...",
  "new_example_chat_prompt": "...",
  "continue_nudge_prompt": "...",
  "group_nudge_prompt": "...",
  "wi_format": "{0}",
  "scenario_format": "{{scenario}}",
  "personality_format": "{{personality}}",

  // 기타: assistant_prefill, claude_use_sysprompt, squash_system_messages, ...
}
```

**감지 규칙** (`detectFormat` 추가): `chat_completion_source` (string) 가 있고 `prompts` 가 배열이고 `prompt_order` 가 배열이면 `sillytavern-prompt-preset`.

### 1.1 `prompts[]` 객체

| 필드 | 타입 | 설명 |
|---|---|---|
| `identifier` | string | 고유 ID. 핵심 프롬프트는 고정 문자열, 사용자 추가는 UUID v4. |
| `name` | string | UI 표시명. 한국어 가능. |
| `role` | `"system"` \| `"user"` \| `"assistant"` | 메시지 역할. |
| `content` | string | 본문. `{{char}}`, `{{user}}` 매크로 치환됨. |
| `system_prompt` | boolean | true 면 삭제 불가 기본 프롬프트. |
| `marker` | boolean | **true 면 컨텐츠 없는 위치 anchor.** chatHistory, worldInfoBefore 등 런타임 자리표시자. |
| `enabled` | boolean | (커스텀 프롬프트만 자체 보유, 핵심은 prompt_order 에서 토글) |
| `injection_position` | `0` \| `1` | 0=RELATIVE (prompt_order 순서), 1=ABSOLUTE (depth/order 값). |
| `injection_depth` | number | ABSOLUTE 일 때 챗 로그 깊이 (기본 4). |
| `injection_order` | number | ABSOLUTE 일 때 우선순위 (기본 100, 큰 값이 먼저). |
| `injection_trigger` | string[] | 생성 타입 트리거 (`['normal', 'continue']` 등). 빈 배열이면 항상. |
| `forbid_overrides` | boolean | 캐릭터 카드의 동명 필드가 덮어쓰는 것을 금지. |

### 1.2 핵심 marker identifier 의미

| identifier | 역할 |
|---|---|
| `main` | 시스템 메인 프롬프트 (컨텐츠 있음). |
| `nsfw` | "Auxiliary Prompt" — 보조 시스템 (NSFW 토글용 기본명). |
| `jailbreak` | 마지막에 들어가는 후속 지침. |
| `chatHistory` | **marker** — 챗 로그 자리. |
| `worldInfoBefore` / `worldInfoAfter` | **marker** — 로어북 매칭 결과 자리. |
| `dialogueExamples` | **marker** — 대화 예시 자리. |
| `enhanceDefinitions` | 캐릭터 정의 보강 지시. |
| `charDescription` / `charPersonality` / `scenario` | **marker** — 시나리오 필드 자리. |
| 유저 페르소나 | 별도 marker를 만들지 않는다. `{{persona}}` 매크로가 있으면 그 위치를 쓰고, 없으면 Stella 기본 위치에 삽입한다. |

### 1.3 `prompt_order[]`

```jsonc
[
  { "character_id": 100000, "order": [
      { "identifier": "main", "enabled": true },
      { "identifier": "worldInfoBefore", "enabled": true },
      ...
  ]},
  { "character_id": 100001, "order": [ ... ] }   // 그룹/특수 캐릭터
]
```

- `character_id: 100000` = **default** (전역 기본 순서)
- `character_id: 100001` = **group** (그룹 챗 기본)
- 그 외 숫자 = 특정 캐릭터 ID 의 오버라이드 (Stella 에서는 거의 안 쓸 듯)

## 2. Stella 통합 스키마 (현재 저장 형태)

현재 구현은 **단일 JSON 파일** 방식이다. 예전의 `_preset.md` + 엔트리별 `.md` 분해 방식은 폐기했다.

```
GGAI/PROMPTS/[프롬프트세트명].json
```

저장 파일은 ST Chat Completion Preset 과 호환되는 raw JSON 을 최대한 그대로 유지한다. Stella 는 이 파일에 아래 메타만 추가한다.

```jsonc
{
  "chat_completion_source": "openai",
  "prompts": [],
  "prompt_order": [],
  "stella": {
    "id": "<uuid>",
    "favorite": false
  }
}
```

### 2.1 저장 정책

- 임포트: 원본 ST JSON 을 그대로 저장하고 `stella.id`, `stella.favorite` 만 주입한다.
- 편집: 기존 raw JSON 이 있으면 `prompts[]`, `prompt_order[character_id=100000].order[]`, `stella` 만 갱신하고 나머지 ST 필드는 보존한다.
- 신규 생성: ST 호환 형태(`prompts`, `prompt_order`, `stella`)로 만든다.
- 폴더를 만들지 않는다. 프롬프트 세트에는 썸네일/에셋이 없고, 한 파일로 보존하는 편이 라운드트립과 백업에 단순하다.

### 2.2 런타임 모델

코드는 디스크의 ST raw 파일을 읽어 내부적으로 `StellaPromptPreset` 으로 복원한다.

```typescript
interface StellaPromptPreset {
  meta: {
    id: string;
    name: string;
    favorite: boolean;
  };
  prompts: StellaPromptItem[]; // 순서 = 컨텍스트 조립 순서
}
```

항목은 두 종류다.

- `kind: "text"`: 실제 메시지 본문. `role`, `content`, `enabled`, `identifier`, `name`, `id` 를 가진다. ST의 `injection_position`, `injection_depth`, `injection_order`, `injection_trigger`, `forbid_overrides` 는 보존하고 컨텍스트 빌더가 사용한다.
- `kind: "marker"`: 런타임 자리표시자. `chatHistory`, `worldInfoBefore`, `worldInfoAfter`, `charDescription`, `charPersonality`, `scenario`, `dialogueExamples`, `memory`, `authorNote`, `enhanceDefinitions` 중 하나다. 유저 페르소나는 marker로 만들지 않고 `{{persona}}` 매크로 또는 기본 삽입 위치로 처리한다.
- Stella 전용 marker 필드(ST 는 무시, `stella_*` 키로 라운드트립 보존):
  - `wrap`(`stella_wrap`): 본문 가공 템플릿.
  - `historyRole`(`stella_history_role`): **chatHistory 마커 전용, 소설모드에서만 적용.** 지금까지의 본문 전체를 어느 롤로 보낼지 — `undefined|"assistant"`(기본, 본문을 어시스턴트 발화로 합침) / `"user"`(본문을 유저 발화로 보냄). 챗 모드는 각 메시지가 제 롤대로 나가므로 무관. 기본값이면 필드를 저장하지 않는다.

### 2.3 identifier 규약

- ST 핵심 identifier(`main`, `nsfw`, `jailbreak`, `chatHistory`, `worldInfoBefore`, `worldInfoAfter`, `dialogueExamples`, `enhanceDefinitions`, `charDescription`, `charPersonality`, `scenario`) 는 가능하면 그대로 유지한다.
- 사용자 추가 프롬프트의 UUID identifier 는 보존한다.
- Stella 내부 id 는 항목 추적용이고, ST identifier 와 별개로 유지한다.
- 임포트 원본 JSON 안에 알 수 없는 identifier나 레거시 persona 관련 항목이 있으면 raw 데이터 보존을 우선하되, Stella 런타임용 marker로 새로 생성하거나 UI에 핵심 marker처럼 노출하지 않는다.

### 2.4 모델/파라미터와의 분리

ST 파일 안에는 모델명, temperature, max token 같은 값이 들어 있을 수 있다. 현재 Stella 에서는 그 값을 활성 설정으로 사용하지 않는다.

활성 모델/파라미터/프롬프트 세트는 다음 중 하나가 들고 있다.

- 열린 세션: `session.meta.modelProfileId`, `session.meta.params`, `session.meta.promptSetId`
- 열린 세션이 없을 때: `PluginData.current`
- 저장해 둔 묶음: `GGAI/PRESETS/<name>.json` 의 `StellaPreset`

즉, `GGAI/PROMPTS/<name>.json` 은 프롬프트 순서와 내용의 원본이고, `GGAI/PRESETS/<name>.json` 은 모델/파라미터/프롬프트 세트를 한 번에 적용하는 북마크다.

## 3. 우측 사이드바 UI (현재 구현)

우측 사이드바 기본 탭은 아래를 노출한다.

1. **프리셋 그리드** — `GGAI/PRESETS/` 의 북마크. 클릭하면 모델/파라미터/프롬프트 세트 묶음을 활성 설정에 적용한다.
2. **모델 섹션** — GGAI Core 의 chat/text 프로필 선택.
3. **파라미터 섹션** — temperature, topP, topK, minP, maxContext, maxOutputTokens.
4. **프롬프트 섹션** — `GGAI/PROMPTS/` 의 프롬프트 세트 선택, 항목 enabled 토글, 드래그 정렬, 이름/역할/본문 편집, 항목 추가/삭제.

> **GGAI Core 와의 책임 분리**: 모델 호출/API 키/스트리밍은 Core 가 담당한다. Stella 는 어떤 프롬프트와 로어북을 어떤 순서로 메시지 배열에 넣을지 결정한다.

## 4. 컨텍스트 빌더 (현재 구현)

`src/util/context-builder.ts` 의 `buildContext(input)` 이 현재 컨텍스트 조립의 중심이다.

1. 활성화된 `prompts[]` 를 순서대로 순회한다.
2. marker 를 실제 내용으로 치환한다.
   - `chatHistory` → 세션 본문 로그
   - `worldInfoBefore` / `worldInfoAfter` → 로어북 매칭 결과
   - `charDescription`, `charPersonality`, `scenario`, `dialogueExamples` → 시나리오 필드
   - `memory`, `authorNote` → 세션 메타
3. `injection_position=1` 인 text 항목과 `at_depth` 로어북을 chat history 특정 깊이에 끼워 넣는다.
4. `injection_trigger` 로 normal/continue 조건을 거른다.
5. `{{char}}`, `{{user}}`, `{{scenario}}` 등 매크로를 치환한다.
6. 고정 메시지 비용을 먼저 빼고, 남은 토큰 예산 안에서 최신 chat history 부터 채운다.

이 함수는 JSON 직렬화 가능한 입출력을 쓰는 순수 함수에 가깝게 유지한다. 나중에 GGAI Core agent tool 로 노출하기 좋은 형태다.
