# 확장 패널 스펙

> 우측 디테일 `확장` 탭에 설정 패널을 추가하는 규약. 내장 패널(요약)과 외부 플러그인이
> 같은 API 로 등록한다. 확장 탭에 새 설정 항목이 필요할 때 이 문서를 먼저 본다.

---

## 개념

`확장` 탭은 개별 UI를 직접 그리지 않는다. `plugin.settingsPanels` 에 등록된
**설정 패널(`SettingsPanel`)** 목록을 **아이콘 런처**(윈도우 앱 아이콘 형태)로 그리는
**호스트**다 (`src/views/detail/expand-section.ts`). 등록된 패널마다 아이콘 하나가 뜨고,
누르면 그 패널의 설정 본문이 아래에 펼쳐진다(한 번에 하나, 다시 누르면 닫힘). 열린 패널
id 는 기억된다. 패널은 스텔라 내장 기능(요약 등)일 수도, 외부 플러그인이 등록한 기능일
수도 있다 — 호스트 입장에서는 구분하지 않는다.

패널 하나 = `{ id, title, icon?, order?, render(body, ctx) }`. `icon` 은 런처에 그릴
Lucide 아이콘 이름(없으면 퍼즐 아이콘). `render` 는 순수하게 "이 body 안에 내 설정
UI를 그린다"만 담당하고, 상태 읽기/쓰기는 전부 `ctx` 로 받는다.

## 등록

```ts
const core = app.plugins.plugins["ggai-stella-engine"];
const unregister = core.registerSettingsPanel({
  id: "my-plugin:foo",       // 다른 확장과 안 겹치게 자기 플러그인 id 로 네임스페이스
  title: "내 기능 설정",
  icon: "settings",            // 런처 아이콘(Lucide 이름). 없으면 퍼즐 아이콘.
  order: 100,                  // 낮을수록 위. 내장 패널은 0~99 를 쓴다.
  render(body, ctx) {
    // ctx.plugin, ctx.getPanelData(), ctx.setPanelData(...), ctx.rerender() 등을 쓴다.
  },
});

// 플러그인 언로드 시
unregister();
```

타입 정의는 `src/services/settings-panel-registry.ts` 의 `SettingsPanel` /
`SettingsPanelContext`.

## 컨텍스트(`ctx`)가 주는 것

| 필드 | 용도 |
|---|---|
| `plugin` | `StellaEnginePlugin` 인스턴스. `plugin.ai`, `plugin.store` 등 접근. |
| `activeSessionFile` | 현재 활성 세션 경로. `null` 이면 세션 밖(패널 자체가 안 그려짐 — 확장 탭은 세션 없을 때 비활성). |
| `settings` | 렌더 시점의 스텔라 활성 설정(`ActiveSettings`) 스냅샷. **내장 패널 전용 필드**(모델/파라미터/번역/삽화/요약)만 담는다. |
| `patchSettings(patch)` | `settings` 의 알려진 필드만 갱신 + 자동 재조회 + 이 패널 재렌더. **스텔라 내장 패널만 쓴다** — 외부 확장이 쓰면 번역/삽화/요약 등 다른 기능과 필드가 겹쳐 충돌할 수 있다. |
| `getPanelData<T>()` / `setPanelData(patch)` | **외부 확장이 쓰는 저장 칸.** 이 패널 id + 활성 세션(없으면 전역) 기준으로 격리된다. 다른 패널이나 스텔라 본체 설정을 건드릴 수 없다. |
| `rerender()` | 이 패널 본문만 다시 그린다 (다른 패널, 탭 바깥 UI에는 영향 없음). |

## 저장 격리 규칙

- **스텔라 내장 패널**(요약 등)은 `patchSettings` 로 `ActiveSettings` 의 정해진 필드(예:
  `summarize`)를 쓴다. 세션이 열려 있으면 세션 메타에, 없으면 전역(`PluginData.current`)에
  저장된다 — 스텔라의 다른 활성 설정과 같은 규칙.
- **외부 확장은 항상 `getPanelData`/`setPanelData` 를 쓴다.** 저장 위치는
  `PluginData.extensionPanelData[패널id][세션파일 또는 "_global"]` 로, 패널 id 로
  네임스페이스되어 다른 패널·스텔라 본체 설정과 절대 충돌하지 않는다. 세션이 열려 있으면
  자동으로 세션별로 나뉘고, 없으면 전역 칸을 쓴다 — 별도 배선 불필요.
- 외부 확장이 세션 데이터(예: `session.json` 자체)에 무언가 저장해야 한다면 이 스펙 밖의
  일이다 — 스텔라의 `StellaStore` 규약(§6, `CLAUDE.md`)을 따로 지켜야 하며, 이 문서의
  `getPanelData`/`setPanelData` 는 그 대신 "가볍고 격리된 키-값 저장"만 제공한다.

## UI 규칙 — 공용 컨트롤 킷 재사용

패널 본문 안의 UI(모델 선택, 프롬프트 선택, 토글, 옵션 그리드, 숫자 입력, 슬라이더)는
직접 마크업을 짜지 않고 다음 함수들을 그대로 쓴다. 그래야 스텔라 내장 설정과 똑같이
생기고 똑같이 동작한다(모델 버튼 꾹 누르기 = Core 프로필 편집 등 디테일 동작 포함).

- `src/views/detail/setting-controls.ts` — `renderModelPicker` / `renderOptionGrid` /
  `renderNumberRow` / `renderEnableToggle` / `renderSliderRow` / `renderCollapsibleShell`.
- `src/views/detail/media-prompt-panel.ts` — `renderMediaPromptPicker`(저장 프롬프트
  선택 그리드 + 추가/편집/삭제/기본값 되돌리기 메뉴 내장) / `renderMediaModelPicker` /
  `renderMediaLorebookPicker`.

패널 자체는 껍데기(아이콘/헤더/닫기)를 직접 그리지 않는다 — 호스트(`ExpandSection`)가
아이콘 런처와 열린 패널의 헤더/닫기 버튼을 자동으로 감싼다. 열린 패널 id 는 기억된다.

## 예시 — 내장 요약 패널

`src/views/detail/panels/summary-panel.ts` 의 `createSummarySettingsPanel()` 이
`patchSettings`(내장 필드 `summarize` 갱신) + `renderMediaModelPicker` /
`renderMediaPromptPicker` / 킷 함수들을 조합한 실제 동작 예시다. `main.ts` 의
`onload()` 에서 `this.registerSettingsPanel(createSummarySettingsPanel())` 로 등록된다.

## 라이프사이클

- `render(body, ctx)` 는 패널이 다시 그려질 때마다(세션 전환, `ctx.rerender()` 호출,
  `patchSettings` 완료 후 등) 호출된다. 매번 `body` 를 비우고 새로 그리므로, 이전
  렌더에서 등록한 DOM 이벤트 리스너를 직접 정리할 필요는 없다(엘리먼트째 사라짐).
- 세션을 넘나드는 비동기 조회(예: 세션 파일 읽기)를 할 때는 렌더 호출 간 경합에
  주의한다 — `render` 클로저 밖(패널 팩토리 함수 스코프)에 카운터를 두고, 비동기 결과가
  돌아왔을 때 그 카운터가 최신 렌더와 일치하는지 확인 후에만 DOM 에 반영한다
  (`summary-panel.ts` 의 `syncSummaryContext` 참고).
