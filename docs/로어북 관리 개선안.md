# 로어북 관리 (확정 설계)

> 상태: **구현 완료.** 배선 상세는 `구현현황.md` "확장 시스템" 의 **로어북 소속·연결 관리** 항목이 진실 소스.
> 이 문서는 "왜 이렇게 만들었는가"(문제·원칙·확정 결정)만 남긴다.

## 문제

- 자동 생성 북 두 종(세션 자동 생성 북 + 시나리오 번역 용어집)이 사용자가 직접 만든 책과 같은 평면(`GGAI/LOREBOOKS/`)에 쌓여 목록이 더러워진다. 비슷한 이름이 많아 세션을 열어보기 전엔 구분이 안 된다.
- 연결 정보가 세션/시나리오 쪽에만 있었다(`session.meta.autoLorebookId`, `scenario stella.translationGlossaryLorebookId`). **로어북 자신은 자기 소속을 몰랐다** — 목록에서 구분 불가, 세션 삭제 후 고아로 남음.
- 역방향(이 책을 누가 쓰는가)을 볼 수단이 없었고, 세션 중에 연결된 책을 고치려면 별도 패널 → 로어북 탭 → 목록에서 찾기까지 가야 했다.

## 원칙

- **저장 위치·파일 형식 불변** (단일 JSON, ST 호환, 기존 스캔/참조 배관 유지). 해결은 소속 메타 + 표시/정리 계층에서.
- **자동 생성 북은 수동 교정이 일상이다 — 접근성을 해치지 않는다.** AI가 전적으로 쓰는 북이라 잘못된 정보가 기록될 수 있고, 로어북은 번역과 달리 노드 되돌리기의 영향을 받지 않으므로(세션을 과거로 되돌려도 북은 그대로) 사용자가 직접 고치는 것이 유일한 복구 수단이다. "숨기기"가 아니라 "자리 정돈" — 자동 북도 항상 클릭 한 번 거리에 있어야 한다.
- **편집 진입은 "지금 이 슬롯에 끼워져 있는 그 책"으로 직행**한다. 별도 패널을 여는 것 자체가 문제가 아니라, 목록에서 다시 찾게 만드는 것이 문제다.

## 확정 결정

1. **소속 메타**: `lorebook.meta.owner = { kind: "session-auto" | "glossary", scenarioId?, sessionId? }` 를 생성 시 기록. 기존 북은 역참조 스캔으로 소급 판정(판정 결과를 굳히는 write-back 은 1회).
2. **목록 분리**: 기본 = "내 서재"(소속 없는 책). 자동 생성 북은 **시나리오별로 묶인 접힘 그룹**(같은 화면 안 — 딴 데로 치우지 않는다), 그룹 안에서도 편집 진입은 클릭 한 번. 검색 중에는 접힘 무시.
3. **수명 연동**: 세션 삭제 시 딸린 자동 북을 함께 삭제할지 확인. "아니오"여도 영구 잔류가 아니다 — 고아가 되어 아래 4번으로 언제든 처리.
4. **고아 일괄 정리**: 연결이 사라진 자동 북을 모아 "N권 정리". 개별 체크 해제 = **순간적 제외**(이번 정리에서만 건너뜀). 삭제는 휴지통 경유.
5. **보호 (정리 대상 영구 제외)**: **보관 플래그**(`meta.keep` — 수명 연동 확인·고아 정리에서 항상 제외, 자동 그룹에는 계속 표시) / **내 서재로 승격**(소속 해제 → 정리 로직과 완전히 무관).
6. **양방향 연결 보기**: 세션 → 연결된 책(줄 클릭 = 그 책 편집 페이지 직행) / 책 → 쓰는 시나리오·세션(줄 클릭 = 거기로 이동). 편집기에서는 아이콘 진입. 삭제 확인에도 사용처 개수를 표시.
7. 자동 북 이름 규칙 보강(시나리오 접두 등)은 **하지 않는다** — 그룹핑 + 배지로 충분.
