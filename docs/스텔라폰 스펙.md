# 스텔라 폰 스펙 (확정 설계, 구현 전)

> 스텔라 폰 관련 작업 전 필독. 이 문서가 설계 진실 소스. 구현이 진행되면 상태는 `구현현황.md`에, 이 문서는 설계 규칙만 유지.

## 개요

세션과 컨텍스트를 공유하는 '폰'. **문자**와 **SNS**로 구성. 페르소나 1명 = 폰 1대(별개의 인물), 캐릭터는 폰 너머의 페르소나들을 서로 다른 사람으로 인식한다(동명이인 허용). PC에서는 폰 프레임 안에, 모바일에서는 프레임 없이 전체 화면.

## 확정 결정 (사용자 확인 완료)

| 항목 | 결정 |
|---|---|
| 문자의 세션 반영 | **기억으로만 주입, 세션 본문 불변** (본문에 문자 블록 표시 안 함) |
| SNS 참여 캐릭터 | **최근 플레이한 시나리오 자동 선별** (별도 설정 없음, lastPlayedAt/playCount 가중) |
| 폰 생성 모델 | **폰 전용 모델 프로필 선택 가능** (미지정 시 기본 챗 프로필) |
| 스트리밍 시작 | **수동 방송 버튼 + 자동 감지 옵션 둘 다** (기본 = 수동만, 자동 감지는 설정으로 켬) |
| 폰 로그인 | **폰 안에서 페르소나 로그인 전환 가능** — 폰 계정만 바뀌고 전역 활성 페르소나·세션 기억은 불변 |
| 생성 언어 | **폰 생성 언어 선택 가능** (문자 답장·SNS 글에 적용, 미지정 시 지시 없음) |
| 번역 | **폰 안에서 번역 기능 사용 가능** (기존 번역 확장 재사용, 메시지/게시글 단위) |

## 핵심 원칙

1. **폰 ID = 페르소나 id.** 폰 관련 모든 생성 지시문에 "발신자는 폰 번호 `<personaId 축약>`의 `<이름>`이다. 번호가 다르면 이름이 같아도 다른 사람이다"를 명시. 캐릭터의 기억 우선순위 = 접속한 페르소나와 공유하는 세션 > 다른 페르소나와의 세션.
1-1. **폰 로그인 ≠ 전역 활성 페르소나.** 폰을 열면 기본은 활성 페르소나로 로그인하되, 폰 안에서 다른 페르소나로 전환 가능(`PluginData.phone.loginPersonaFile` 영속, 폰 안에서만 유효). 로그인 전환은 폰 계정(문자함·SNS 시점·연락처)만 바꾸고 전역 활성 페르소나와 세션의 페르소나 기억(`meta.personaFile`)은 절대 건드리지 않는다. 문자의 "현재 세션 첨부"(원칙 3)는 로그인 페르소나 = 그 세션의 페르소나일 때만.
2. **아는 것만 안다.** 문자 답장 생성 시 캐릭터가 아는 것 = ①문자 스레드에 적힌 내용 ②그 페르소나와 공유한 세션 경험(첨부분). 문자에 안 적힌 세션 디테일을 문자에서 아는 척하지 않도록 지시문으로 제한(모델 한계는 인정하되 지시는 명확히).
3. **현재 세션 첨부.** 현재 세션 중인 캐릭터에게 문자를 보내면 현재 세션의 최근 본문+요약이 함께 감 → "같이 있는데 왜 문자해?" 같은 상황 인지 답장 가능. 세션에 없는 캐릭터는 문자 이력+과거 공유 세션 요약만.
4. **연락처는 파생 데이터.** 그 페르소나로 세션을 1개 이상 함께 한 시나리오만 문자 가능. 세션 기록에서 계산하며 별도 저장하지 않는다(엑스트라 연락처는 예외 — 메시지 파일에 저장).
   - **후보 판정은 느슨하다** — 이 목록은 캐릭터가 많아 헷갈리는 걸 막는 정리 장치이고, "같이 대화할 자격" 심사가 아니다. 판정은 `session.meta.personaIds`(그 세션을 함께한 페르소나 **전원**, 추가만 하고 지우지 않는다)를 보고, `personaFile`(지금 이 세션의 페르소나 하나) 은 옛 세션 호환용 보조 키다. 플레이 도중 페르소나를 바꿔도 양쪽 페르소나 폰에 다 남는다. 페르소나 기록이 아예 없는 옛 세션은 **모든 페르소나의 후보**로 넣는다. id 기준이라 페르소나 파일 이름이 바뀌어도 유지된다.
5. **세션 본문 불변.** 문자/SNS는 세션 노드를 만들지 않는다. 세션 → 폰 방향은 컨텍스트 첨부, 폰 → 세션 방향은 생성 시 컨텍스트 주입(기억)뿐.
6. **비용 상한 필수.** 갱신은 1회 1통 + 전역 스로틀(5분) + **미응답 상한**(답장 안 한 수신 스레드가 기본 2개 쌓이면 쉼, 설정 가능) 안에서만. SNS 게시글 상한(기본 3)은 PH3에서. 상한 없는 자동 생성 금지.

## 데이터 형식

```
GGAI/PHONE/
├── <personaId>/messages.json   # 그 페르소나 폰의 문자 스레드 전체
├── sns.json                    # 볼트 공용 SNS 피드 (모든 세계관이 네트워크 공유)
└── assets/                     # 카메라 생성물·업로드·캐릭터 사진 PNG
```

- **messages.json**: 스레드 배열. 스레드 = `{id, kind: "scenario"|"extra", scenarioId?, extraName?, messages[]}`. 메시지 = `{id, from: "persona"|"other", text, createdAt, sessionFile?}`(sessionFile = 보낼 당시 첨부한 세션, 기억 주입 시 매칭 키).
- **sns.json**: 게시글 배열. 게시글 = `{id, author: {kind: "scenario"|"persona"|"extra", id?, name}, text, image?: {asset?|caption}, createdAt, replies[], stream?: {sessionFile, live}}`. 답글 구조 동일(1단 깊이).
- 폰 전역 설정 = `PluginData.phone`: `{loginPersonaFile?, modelProfileId?, language?, translation?: {enabled, lorebookIds?}, triggers: {onOpen, randomInSession, periodic: {enabled, minutes}, keywords: {enabled, custom[]}}, caps: {messages, posts}, streamAutoDetect}`.
- 메시지/게시글에 번역 variant 저장 가능: `{translation?: {text, variants?}}` — 원문은 불변, 표시 토글로 원문↔번역 전환(번역 메모리 개념은 세션 번역과 동일하되 폰은 항목 단위).
- 모든 읽기/쓰기는 StellaStore 경유(`getPhoneMessages`/`savePhoneMessages`/`getSnsFeed`/`saveSnsFeed` + `phone-changed` 계열 이벤트). 이미지 저장은 `saveSessionAsset` 패턴 재사용.

## 문자

- UI = 챗 세션 말풍선 스킨(`chat-format.ts`) 재사용. 폰 안 스레드 목록 + 1:1 대화창. 챗 세션 플레이 중에도 폰 안에서 별개의 문자 가능(세션 = 현실, 폰 = 문자 컨셉). 아이콘과 날짜 표시 등 챗 세션과 같은 ui 적용.
- 답장 생성 = PhoneService(폰 전용 모델) — 재료: 캐릭터 카드 + 문자 스레드 이력 + (현재 세션 중이면) 세션 tail/요약 + 핵심 원칙 1·2·3 지시문. 비스트리밍 1회 호출(선채팅 `send` 패턴). `phone.language` 지정 시 "이 언어로 답하라" 지시를 덧붙임(SNS 게시글·코멘트·엑스트라도 동일).
- **번역**: 폰 설정의 토글 **하나**가 전부 — 켜면 문자/SNS/방송이 생성되는 대로 자동 번역하고 번역본을 보여준다(기본 꺼짐, 별도 "자동 번역" 옵션 없음). 결과는 항목의 번역 variant 로 저장(재번역 방지), 원문↔번역 표시 토글과 개별 재번역은 그대로. 프롬프트/모델/로어북은 전역 번역 설정을 그대로 재사용한다(폰 전용 로어북 없음).
- **세션 기억 주입**: 확장 레지스트리 `contributeContext` 신규 슬롯 `phone` — `planSessionRequest`가 수집(미리보기 byte 동일 대전제 준수). 내용 = 그 캐릭터와의 최근 문자 발췌(항상) + SNS 항목(그 캐릭터가 작성/답글 = 100%, 나머지는 확률적 샘플). 시간 기준이라 분기 갈아타기에 안전(문자는 폰에서 실제로 일어난 일 — 분기와 무관).
- **엑스트라 문자**: 모르는 번호 발신. 현재 세션 분위기(tail)를 재료로 생성(의문의 문자·스팸·협박 등 리얼리즘). 스레드 kind="extra"로 저장, 연락처엔 "알 수 없는 번호"로 표시.

## SNS

- 종류 = 게시글 / 답글 / 스트리밍. 작성자 = 캐릭터·페르소나(사용자 직접 작성)·엑스트라.
- **참여자 선별(자동)**: 최근 플레이한 시나리오를 lastPlayedAt/playCount 가중 샘플. 갱신 1회당 caps.posts 안에서 게시/답글 생성. 우선순위는 핵심 원칙 1.
- **생성 재료(첨부량)** — `PhoneService.collectSnsMaterial`:
  - **이벤트**: 최근 세션(수정 시각순, 열린 세션은 무조건 선두) 상위 N개 본문을 세션당 토큰 예산으로 첨부. N = `snsSessionCount`(기본 3), 예산 = `snsSessionTokens`(기본 4000). 절단은 `trimToTokens`(tail=최신 우선). `buildEventBlock`.
  - **활성 로어북**: 각 이벤트 세션에 대해 그 첨부 본문 기준으로 `matchLorebookEntries`(상시 + 키워드 매칭)를 돌려 활성화된 엔트리만 붙인다. 전체 덤프도 요약도 아님(사용자 확정).
  - **세계 로스터**: 시나리오는 캐릭터가 아니라 **세계**다 — 등장인물 파악은 설명·로어북에서. 최근 등장 가중 비복원 샘플(`pickRecencyWeightedSample`)로 시나리오 10개, 각 **설명 + 로어북 전체**(`buildWorldReference`, head 절단 1400토큰). 엔진 고정 데이터.
    - **최근 등장 = 개인 세션 + 그룹 세션 참가**: `recencyById` = max(lastPlayedAt, 자기 세션 modifiedAt, **참가한 그룹 세션 modifiedAt**). 그룹 세션은 호스트뿐 아니라 멤버(`group.members[].scenarioId`) 전원의 최근 등장으로 친다.
  - **뷰어 목록**: `getUsers()` 페르소나 목록(로그인 뷰어 표시). 절대 그 명의로 글 쓰지 않게 지시. 엔진 고정 데이터.
  - charByName = 로스터 + 이벤트 세계의 메인 캐릭터 작성자 귀속.
- **설정 그룹핑**: 확장 패널은 문자 세부 설정 / SNS 세부 설정 / 갱신 타이밍(공용) 세 묶음. 문자 = 프롬프트·이력·세션장면·미응답상한, SNS = 프롬프트·세션첨부개수·세션당토큰·활동상한·방송자동감지.
- **스트리밍**: 세션 공용 메뉴/폰에서 "이 장면 방송 중" 토글(수동 기본) + 설정 켜면 키워드·상황 자동 감지도. 방송 = 세션 최근 장면 요약이 방송 화면(삽화 있으면 썸네일), 그 자리에 없는 캐릭터들의 코멘트가 달림 → 코멘트 단 캐릭터는 촬영 장소·상황 정보를 기억으로 획득(주입 100% 규칙에 걸림).

## 갱신 트리거 (중복 선택 가능)

1. 폰 UI를 켰을 때
2. 세션 중 랜덤 기회(5~30분 지터)
3. 정기 갱신(기본 1시간, 사용자 지정, 옵시디언 활성 시만)
4. 세션 생성문에 키워드 등장 시 — 기본 사전 = 폰/문자/메시지/SNS/스트리밍/방송/카메라/사진 계열 한·영·일 3개 국어 + 사용자 추가

구현은 선채팅 `ProactiveService` 스케줄러 패턴(1분 틱 + 영속 예약 + 캐치업 버스트 방지) 재사용. 갱신 실행 = caps 안에서 "답장 사유 있는 문자"와 "SNS 신규 글" 생성.

## 이미지

- **갤러리 업로드(사용자)**: 이미지 + 캡션 필수 입력 — 이미지 인식 안 되는 모델에게는 캡션이 정보.
- **카메라**: 프롬프트 직접 입력 → Core `image()` → PHONE/assets 저장 + 대시보드 갤러리에 시나리오명 대신 "스텔라 폰" 타이틀로 등록.
- **캐릭터 사진 업로드**: 삽화 생성 메커니즘(프롬프트 생성 LLM → image) 재사용. 이미지 모델 미사용 시 캡션 텍스트만으로 대체("○○와 △△가 같이 찍은 사진") — 캡션이 곧 다른 캐릭터·모델의 정보.

## UI (2026-07-14 확정 — 홈 화면 모델)

- 뷰 타입 `ggai-stella-phone`. PC = 폰 프레임 렌더, 모바일 = 프레임 없이 풀 화면(`Platform.isMobile` 분기).
- **폰 = 홈 화면 + 앱 모델** (탭 바 아님, 이입 우선): 폰을 켜면 배경화면(월페이퍼) + 시계 + 앱 아이콘 그리드. 앱을 탭하면 그 앱 화면으로, 하단 홈 바(알약)로 홈 복귀. 새 기능(카메라/갤러리/스트리밍)은 홈에 앱 아이콘을 추가하는 방식으로 확장.
  - 현재 앱: **메시지**(문자), **스텔라 네트워크**(SNS). 예정: 카메라/갤러리(PH5).
  - 상단 상태 바: 시계 + 로그인 페르소나 칩(전환 메뉴) — 어느 화면에서든 접근.
- **메시지 앱 스킨 = 챗 세션과 동일**: 챗 세션 말풍선 공용 클래스(`.ggai-chat-msg`/`avatar`/`name`/`bubble`) 재사용 — 아바타(캐릭터 표지/페르소나 썸네일)와 이름 라벨이 보인다. 폰 안에서는 아바타 크기만 축소.
- 설정은 확장 탭 패널(`registerSettingsPanel`)로: 사용 토글, 폰 모델, 생성 언어, 번역(토글 하나), 트리거 4종, 생성량 상한, 키워드 편집, 스트리밍 자동 감지.

## SNS 계정 모델 (2026-07-15 확정 — 시나리오 ≠ 캐릭터)

- **시나리오는 "세계"이지 계정이 아니다.** 시나리오는 캐릭터 카드일 수도, 여러 인물이 사는 시뮬레이션/소설/세계관일 수도 있다. SNS 작성자는 항상 **인물**: ①이름 있는 캐릭터(`SnsAuthor.kind:"character"`, 시나리오 stella id 귀속 — 카드 이름과 일치할 때), ②익명 핸들/엑스트라(`kind:"extra"` + `world` 서브라벨 — "익명의 목격자" 같은 자유 발명), ③페르소나. 세계 타이틀 명의의 글 금지(생성 지시문에 명시).
- 생성 배치는 세계(시나리오)별 최근 사건을 재료로 주고, 그 세계의 메인 캐릭터·장면 속 인물·익명 엑스트라가 섞여 투고하게 한다. 뷰어(페르소나) 명의 사칭은 파싱 단계에서 버린다.
- **시나리오 공식 계정**(`kind:"scenario"`, 프로필 카드 꾸미기)은 예약 — 프로필 화면과 함께 추후 확장.
- 좋아요: 게시글/댓글에 생성 시 기본값(likes), 사용자는 ♥ 탭으로 가감(likedBy=페르소나 id 목록).

## SNS 스레드 구조 (2026-07-14 확정 — 입체 댓글)

- 답글은 **2단 트리**: 게시글 → 답글 → 답글의 답글(`SnsReply.parentId`). 렌더는 대댓글 들여쓰기.
- 생성 배치는 게시글을 **댓글이 이미 달린 채로** 만들 수 있고(포스트 + comments 동반), 기존 글/댓글/뷰어(페르소나)의 글·댓글에도 답글을 단다. 상한 = 활동 총합(게시글+댓글, 기본 6, 배치 1회 호출 유지).
- 엑스트라(배경 인물) 활동은 배치당 최대 2개.

## 단계 (국소 완성 — 각 단계가 빌드+수동 검증까지 끝나야 다음)

- **PH1 폰 기반 + 문자**: PHONE 폴더/타입/store, 폰 뷰(문자 탭만) + 로그인 페르소나 전환, 연락처 파생, 문자 송수신(현재 세션 첨부·생성 언어 포함), `phone` 컨텍스트 슬롯(문자 기억 주입)
- **PH2 갱신 트리거 + 엑스트라 문자**: 스케줄러, 트리거 4종 설정 패널, 상한, 엑스트라 발신
- **PH3 SNS 피드**: 게시글/답글, 참여자 자동 선별, 확률 주입(직접 작성 100% 규칙)
- **PH4 스트리밍**: 수동 방송 토글 → 코멘트 생성 → 정보 전파, 자동 감지 옵션
- **PH5 이미지 3종 + 번역**: 갤러리 업로드+캡션, 카메라(대시보드 갤러리 연동), 캐릭터 사진(캡션 대체 포함), 폰 안 번역(항목 단위 variant + 표시 토글)

## 가드레일

- 문자/SNS 생성이 세션 노드·본문을 절대 만들거나 수정하지 않는다.
- `phone` 컨텍스트 기여는 `planSessionRequest` 한 곳 — 미리보기와 전송본 byte 동일 대전제 유지.
- 폰 뷰도 EditGuard·국소 갱신 규약 동일 적용(문자 입력 중 재렌더 금지).
- 갱신은 항상 caps 안에서만. 캐치업 시 버스트 금지(선채팅과 동일).
- 페르소나 삭제/이름 변경 시 PHONE/<personaId> 배관은 sessionAnchor 와 같은 rename/delete 추적 패턴을 따른다.
