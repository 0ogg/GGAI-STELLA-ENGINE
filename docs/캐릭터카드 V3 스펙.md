AI(LLM)를 이용한 바이브 코딩(Vibe Coding)으로 \*\*Character Card V3(CCv3) 임포트/익스포트 기능\*\*을 구현할 때, 프롬프트 컨텍스트로 바로 집어넣기 좋도록 \*\*데이터 구조, 파일 포맷 처리, 호환성 핵심 규칙\*\*만 압축해 드립니다.



프롬프트 생성 로직(Decorators, Macros)은 파일 입출력(Import/Export) 자체와는 무관하므로 제외하고, \*\*파싱과 직렬화(Serialization)\*\*에 필요한 내용만 담았습니다.



\---



\### 💾 1. 지원 파일 포맷 및 입출력 규칙 (Import/Export)



\*\*1) PNG / APNG\*\*

\*   \*\*Export:\*\* JSON 데이터를 `utf-8 -> base64`로 인코딩하여 \*\*`ccv3`\*\* 라는 이름의 `tEXt` 청크에 삽입.

\*   \*\*Import:\*\* `ccv3` 청크를 우선적으로 찾아서 디코딩.

&#x20;   \*   \*호환성:\* `ccv3`가 없고 `chara` 청크(V2 규격)만 있다면 V2로 임포트하되, 사용자에게 경고 표시 권장. 두 청크가 모두 있으면 무조건 `ccv3` 사용.



\*\*2) JSON\*\*

\*   단일 JSON 파일. 아래 2번 항목의 구조를 그대로 따름.



\*\*3) CHARX (.charx)\*\*

\*   \*\*구조:\*\* 압축(ZIP) 파일. 암호화 금지, 파일/경로명은 ASCII만 사용.

\*   \*\*필수:\*\* ZIP 루트 디렉토리에 \*\*`card.json`\*\* 이름으로 CCv3 JSON 파일 존재해야 함.

\*   \*\*에셋(Assets) 경로:\*\* `assets/{type}/{category}/` 형태 유지 권장 (예: `assets/icon/images/`, `assets/background/audio/` 등).

\*   \*\*URI 접근:\*\* JSON 내부에서 charx 안의 파일을 참조할 때는 `embeded://path/to/asset.png` 형식 사용 (대소문자 구분).

\### 🧱 2. 핵심 데이터 구조 (TypeScript Interface)

AI에게 모델/스키마를 작성시킬 때 이 구조를 그대로 제공하세요. (V2의 필드를 포함한 V3 통합 스펙입니다.)



```typescript

interface CharacterCardV3 {

&#x20; spec: 'chara\_card\_v3'; // \[필수] 반드시 이 값이어야 함

&#x20; spec\_version: '3.0';   // \[필수] 3.0 이상인지 실수(float)로 파싱하여 체크

&#x20; data: {

&#x20;   // --- V2에서 계승된 필드 ---

&#x20;   name: string;

&#x20;   description: string;

&#x20;   tags: string\[];

&#x20;   creator: string;

&#x20;   character\_version: string;

&#x20;   mes\_example: string;

&#x20;   extensions: Record<string, any>;

&#x20;   system\_prompt: string;

&#x20;   post\_history\_instructions: string;

&#x20;   first\_mes: string;

&#x20;   alternate\_greetings: string\[];

&#x20;   personality: string;

&#x20;   scenario: string;



&#x20;   // --- V3에서 변경/추가된 필드 ---

&#x20;   creator\_notes: string;

&#x20;   character\_book?: Lorebook; // 하단 Lorebook 인터페이스 참고

&#x20;   

&#x20;   // \[V3 핵심] 에셋 리스트 (없을 경우 기본값 처리 필요 - 하단 규칙 참조)

&#x20;   assets?: Array<{

&#x20;     type: string; // 'icon', 'background', 'user\_icon', 'emotion' 등

&#x20;     uri: string;  // HTTP(S) URL, base64, 'embeded://...', 'ccdefault:'

&#x20;     name: string; // 에셋 식별자 (type이 'icon'일 때 'main'이 메인 아이콘)

&#x20;     ext: string;  // 'png', 'webp' 등 확장자 소문자 (없으면 'unknown')

&#x20;   }>;

&#x20;   

&#x20;   nickname?: string; // 프롬프트 내 {{char}} 매크로 치환용 우선 이름

&#x20;   creator\_notes\_multilingual?: Record<string, string>; // ISO 639-1 언어 코드 키 (ex: 'ko', 'en')

&#x20;   source?: string\[]; // 출처 URL 또는 ID 배열

&#x20;   group\_only\_greetings: string\[]; // \[필수] 그룹챗 전용 인사말 (비어있어도 배열 존재해야 함)

&#x20;   creation\_date?: number; // Unix Timestamp (초 단위, UTC)

&#x20;   modification\_date?: number; // Unix Timestamp (초 단위, UTC)

&#x20; };

}



interface Lorebook {

&#x20; name?: string;

&#x20; description?: string;

&#x20; scan\_depth?: number;

&#x20; token\_budget?: number;

&#x20; recursive\_scanning?: boolean;

&#x20; extensions: Record<string, any>;

&#x20; entries: Array<{

&#x20;   keys: string\[];

&#x20;   content: string; // 프롬프트에 삽입될 텍스트 (내부에 @@ 데코레이터 포함될 수 있음)

&#x20;   extensions: Record<string, any>;

&#x20;   enabled: boolean;

&#x20;   insertion\_order: number;

&#x20;   case\_sensitive?: boolean;

&#x20;   

&#x20;   // V3 변경/추가 항목

&#x20;   use\_regex: boolean; // true면 keys를 정규식으로 처리

&#x20;   constant?: boolean; // \[V3 구현 필수] true면 조건 무시하고 항상 활성화

&#x20;   

&#x20;   // 선택 항목

&#x20;   name?: string;

&#x20;   priority?: number;

&#x20;   id?: number | string;

&#x20;   comment?: string;

&#x20;   selective?: boolean;

&#x20;   secondary\_keys?: string\[];

&#x20;   position?: 'before\_char' | 'after\_char';

&#x20; }>;

}
```

\### ⚠️ 3. 파싱 및 호환성 유지를 위한 핵심 "Must" 규칙



코딩 시 AI에게 다음 조건들을 반드시 예외 처리하라고 지시하세요.



1\.  \*\*알 수 없는 필드(Unknown Fields) 보존 규칙 (가장 중요)\*\*

&#x20;   \*   \*\*Import 시:\*\* 스펙에 없는 필드가 JSON에 있더라도 \*\*절대 삭제하거나 무시해서는 안 됩니다.\*\*

&#x20;   \*   \*\*Export 시:\*\* 임포트할 때 보존해둔 알 수 없는 필드들을 그대로 포함해서 내보내야 합니다. (미래 버전 하위/상위 호환성 목적)

2\.  \*\*`assets` 필드 기본값 처리\*\*

&#x20;   \*   임포트 시 `assets` 필드가 비어있거나(`undefined`), 카드 이미지가 PNG/APNG인 경우, 앱 내에서는 아래의 기본 객체가 있는 것처럼 취급해야 합니다.

&#x20;       ```json

&#x20;       \[{ "type": "icon", "uri": "ccdefault:", "name": "main", "ext": "png" }]

&#x20;       ```

&#x20;   \*   메인 아이콘을 찾을 때는 `type === 'icon'` 이고 `name === 'main'` 인 요소를 찾아야 합니다.

3\.  \*\*날짜 형식 (Timestamps)\*\*

&#x20;   \*   `creation\_date`와 `modification\_date`는 밀리초(ms)가 아닌 \*\*초(seconds) 단위의 Unix Timestamp (UTC)\*\* 입니다.

&#x20;   \*   Export 시 카드가 수정되었다면 `modification\_date`를 현재 시간(초)으로 갱신해야 합니다.

4\.  \*\*V2 스펙과의 호환성 방어\*\*

&#x20;   \*   V2 카드를 읽어 V3로 저장(마이그레이션)할 때, `spec`은 `"chara\_card\_v3"`, `spec\_version`은 `"3.0"`으로 강제 덮어쓰기 해야 합니다.

&#x20;   \*   `group\_only\_greetings` 필드는 V2에 없으므로, 변환 시 빈 배열 `\[]` 이라도 무조건 넣어줘야 합니다.
